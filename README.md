# 开仓前 · 开仓与止损卡

任务 01–08 的本地单人工作台：个人登录后查看 Binance USDT 合约账户，按预算、单层或双层止损及成本假设即时试算；止损可保存为本地百分比模板，在当前币种和方向上复用。刷新并通过资金、账户档位及强平缓冲检查后，生成市价或普通 GTC 限价开仓卡，由用户在 Binance 手动带止损开仓。返回刷新后核验实际风险、强平缓冲与止损覆盖；限价部分成交须先人工撤余单，再按实际仓位复核，双层近端退出后计入本单已实现损益与全部费用。关闭页面、重新登录和服务重启后可恢复本单，返回页面或恢复联网后重新查询。前端使用 Vue 3、TypeScript 和 Vite，后端继续使用 Node 内置模块；共享金额计算保持 BigInt 定点实现。工具不下单或修改账户设置，卡片不代表已挂好止损。

## 本机启动

需要 Node.js **22.21.0 或更高的受支持版本**（支持原生 TypeScript 和 `--use-env-proxy`），使用 **pnpm 11.7.0**。

1. `pnpm install --frozen-lockfile` 安装锁定依赖。
2. 参考 [`.env.example`](.env.example)，在本机 `.env` 中设置至少 12 字符的独立 `APP_PASSWORD`。已有 `.env` 时合并变量，**不要覆盖原文件**。API Key、Secret、个人密码都只填写在本机，不发到聊天。
3. 构建前端并首先运行模拟模式，无需 API 凭据：

```sh
pnpm build
APP_MODE=demo pnpm start
```

打开 <http://127.0.0.1:3000>，用 `APP_PASSWORD` 登录。模拟数据始终标识“模拟数据”，不发送任何 Binance 请求，也不代表真实账户验证。

连接真实账户时，在 `.env` 中配置专用 **HMAC** 类型的 `BINANCE_API_KEY`、`BINANCE_API_SECRET`，然后重启：

```sh
APP_MODE=real pnpm start
```

默认就是 `real`；没有完整凭据时可登录，但账户显示未连接。失败不会切换模拟数据。已有 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` 由 Node 原生代理支持读取，无需复制代理地址到源码。不要启用 Node 的 HTTP 调试日志，以免记录请求头和签名 URL。

个人会话有效期 8 小时，仅保存在服务内存；退出、服务重启或到期后需重新登录。10 次失败登录后限制 15 分钟。所有页面和账户响应禁止缓存；浏览器只获得展示所需字段，不接收 API 凭据或原始账户响应。

## 手机连接本地电脑

手机和电脑处于同一可信局域网。默认 HTTP 仅供电脑本机使用；局域网需要 **HTTPS**，防止密码和会话明文传输。服务绑定 `APP_ORIGIN` 中指定的本机地址，不自动绑定所有网卡。

若已有本地可信证书，直接配置下面三个变量即可。也可用 OpenSSL 生成本地测试证书（将示例 IP 换成电脑局域网 IP）：

```sh
LAN_IP=192.168.1.100
mkdir -p .local
openssl req -x509 -newkey rsa:2048 -nodes -days 30 \
  -keyout .local/key.pem -out .local/cert.pem \
  -subj '/CN=Entry Guidance Local' \
  -addext "subjectAltName=IP:${LAN_IP},IP:127.0.0.1,DNS:localhost" \
  -addext 'basicConstraints=critical,CA:TRUE'
chmod 600 .local/key.pem
```

在手机上安装并信任自己生成的 `cert.pem`（**不要传输 `key.pem`**）。在 `.env` 中设置以下变量，替换 IP 后重启 `pnpm start`：

```dotenv
APP_ORIGIN=https://192.168.1.100:3000
TLS_CERT_FILE=.local/cert.pem
TLS_KEY_FILE=.local/key.pem
```

手机访问该 HTTPS 地址；电脑也使用同一个地址。HTTPS 会话带 `Secure` 标记。证书及私钥放在被 Git 忽略的 `.local/`。本项目未配置公网部署或反向代理，不应将本地端口直接暴露到公网。

## 读取和金额口径

账户读取使用以下 **GET** 签名请求，禁止重定向、任意地址、任意参数或交易请求：

| 接口 | 用途 |
| --- | --- |
| `api.binance.com/sapi/v1/account/apiRestrictions` | 确认读取权限，拒绝交易、提现、划转等权限；关键权限字段缺失时停止。 |
| `api.binance.com/sapi/v1/portfolio/account` | 排除统一/组合保证金账户，含 Pro；只有明确的 `-21001 USER_IS_NOT_UNIACCOUNT` 错误才继续。其他失败不当作普通账户证明。 |
| `fapi.binance.com/fapi/v2/account` | 要求 `multiAssetsMargin=false`，读取唯一的 USDT 资产。 |

权益 = USDT 的 `walletBalance + unrealizedProfit`，并检查与 `marginBalance` 一致；可用余额直接采用该资产的 `availableBalance`，不减第二次已占保证金。不使用账户汇总值、`crossUnPnl` 或提现额度替代。金额以 8 位小数的 BigInt 计算；字段不合法、超出支持精度或口径不一致时停止展示新结果。

每次完整查询总计最多 10 秒。页面显示本次查询时间，不将交易所保留的 `updateTime=0` 当作查询时间。刷新失败保留原账户快照及原时间并标明过期，撤销试算结果；整页重新打开时重新查询。结果只表示该时点快照，不表示持续连接或可开仓状态。试算读取账户 V2 中目标币种的 `positionAmt`、`positionSide` 和 `isolated`，仅允许空仓、逐仓与单向持仓。

账户快照独立通过 `/api/account` 按固定 3 秒周期刷新，无需先选择币种。仅在页面可见、联网且会话有效时查询；账户查询或完整查询尚未完成时跳过本轮，手动查询、修改输入、离开页面及卸载会取消旧账户请求，迟到响应不能覆盖新状态。自动账户查询只更新账户区数值和查询时间，不更新行情、草稿估值或成交核验的查询时间，也不重新启用旧卡。发现权益或可用余额变化时撤销旧估值、卡片与核验通过状态，等待原有节奏的完整查询重新确认；失败保留旧快照并明确标注过期，同样撤销可用状态。后续账户查询成功仅恢复账户展示，完整查询通过后才恢复相应可用状态。

选择币种后，同次查询还使用以下固定 **GET** 接口。公共行情请求不携带 Key 或签名；私有请求仅接受经过校验的币种参数，前端无代签入口。

| 接口 | 用途 |
| --- | --- |
| `/fapi/v1/exchangeInfo`（公共） | 筛选交易中的 USDT 本位永续，读取 `PRICE_FILTER`、`LOT_SIZE`、`MARKET_LOT_SIZE`、`MIN_NOTIONAL` 及 `marketTakeBound`；限价另须确认 `LIMIT`、`GTC` 支持及 `PERCENT_PRICE`。不以显示精度替代步长。 |
| `/fapi/v1/ticker/bookTicker`、`/fapi/v1/premiumIndex`（公共） | 买卖报价、标记价及各自数据时间。 |
| `/fapi/v2/ticker/price`（公共） | 最新成交价，用于官方市价下单成本估值；保留最后成交时间。 |
| `/fapi/v1/leverageBracket` | 读取该账户、该币种的杠杆上限、名义价值边界、维持保证金率和速算额。 |
| `/fapi/v1/commissionRate` | 读取当前币种的账户 taker 费率，开平仓均采用该值；缺失或异常时阻断，不手填覆盖，不假定额外折扣。 |
| `/fapi/v1/positionSide/dual` | 再确认账户单向持仓。 |
| `/fapi/v1/openOrders`、`/fapi/v1/openAlgoOrders` | 分别查询目标币种普通与条件挂单；任一非空即要求用户处理，包括只减仓或整仓退出委托。 |

旧仓位、旧委托或模式不符合时撤销数量，保留输入和具体处理原因。工具不清仓、撤单或改变模式。模拟模式仅提供明确标注的 BTCUSDT / ETHUSDT 虚拟报价与规则；真实模式币种列表来自 Binance。

## 单层试算口径

市价多头参考卖一、空头参考买一；同一滑点百分比分别用于入场与止损退出的不利方向。限价采用用户委托价，不叠加入场滑点；止损退出仍按不利市价滑点估算。限价须符合实际价格步长及范围，不静默改价；`PERCENT_PRICE` 多头只检查标记价对应上界，空头只检查下界。手续费包括开平两次 taker 费用，普通限价不假定 maker；资金费为可选固定 USDT 预留，空值或零明确显示“未预留资金费”。止损是标记价触发的止损市价、整仓退出、关闭价格保护。

通过公开业务函数 `generateDraft(input, snapshot)` 计算。金额、价格、数量和费率输入最多支持 8 位小数，超过精度明确拒绝；使用 BigInt 保留乘积全精度。止损按实际 tick 及价格下限多头向下、空头向上取整；数量按适用数量上下限及步长向下取整，复算风险。限价使用 `LOT_SIZE`，最小开仓名义价值按委托价；市价使用市价数量规则，最小名义价值按标记价。止损退出使用整仓语义，不把开仓的最小名义价值套到止损。计划亏损展示向上取到 8 位小数，比例预算换算向下保留 8 位 USDT 小数；均不扩大预算。

首次预算、止损、滑点、杠杆及最低强平缓冲均为空，权益由账户读取。预算比例范围为 `(0,100]`%；滑点为 `[0,100)`%；预算须大于资金费预留。固定金额预算不等于可投入资金：草稿保留价格风险试算，正式卡还需下述资金和强平检查。

进入页面、换币及手动刷新时读取完整快照；修改输入立即清除旧估值，停止输入 500 毫秒后重新查询。选定币种、页面可见且联网时，每次查询结束 10 秒后自动刷新，不重叠请求；返回页面或恢复联网立即查询。查询中、失败或数据过期时不保留可用估值，迟到响应不能覆盖新输入。杠杆下方的预估强平价显示两位小数（正数四舍五入后为零时显示 `<0.01`），计算和风险检查仍保留原精度。

## 正式开仓卡计算口径

公开入口 `generateEntryPlan(input, snapshot)` 复用草稿的精确风险计算。数量同时满足风险预算、USDT 可用余额、可选本单资金上限、账户所选杠杆名义价值上限及适用数量规则（市价取普通/市价规则交集；限价仅用普通规则）。仅向下缩量，保持原止损和杠杆；不能满足最小数量或该订单类型的最小开仓名义价值时拒绝。整仓止损输出关闭全部仓位语义，不构造固定退出数量。

令数量为 `q`、杠杆为 `L`、方向 `D`（多 +1、空 -1）、标记价 `M`、委托价 `E`、不利成交估值 `Ew`、账户 taker 费率 `f`。市价下单估值 `A = 最新成交价 × 1.0015`，多空相同；限价多头 `A = E`，限价空头 `A = max(最新成交价 × 1.0015, M, E)`。开仓浮亏使用的价格 `V` 在市价时为 `A`，限价时为 `E`：

```text
初始保证金 = q × A / L
开仓浮亏 = q × max(0, D × (V - M))
开仓费用预留 = q × max(A, Ew) × f
资金需求 = 初始保证金 + 开仓浮亏 + 开仓费用预留
```

费用取两个估值中较大者是本工具的预留假设；止损预算仍按 `Ew` 计算两次手续费。名义价值上限同时约束 `M`、`A`、`Ew`；市价不利成交估值不能超出交易所市价成交边界。资金总需求向上展示到 8 位 USDT 小数，比较使用未取整乘积。

强平采用本次已确认模型：`WB = q × Ew / L − q × Ew × f`，不计额外/自动追加保证金及未来资金费变化。`WB` 是假设逐仓本金，不宣称等于交易所实际逐仓钱包余额，也不保证是其下界。每档维持保证金率 `r`、速算额 `c` 代入官方逐仓公式的单向化简：

```text
多头 LP = (q × Ew − WB − c) / (q × (1 − r))
空头 LP = (q × Ew + WB + c) / (q × (1 + r))
有方向缓冲 = D × (绝对止损 − LP) / 入场参考价 × 100%
```

每个候选强平价以未取整 `q × LP` 检查所属档位，跨档重新计算。最终强平价多头向上、空头向下保留到 8 位，按此不扩大缓冲的值检查用户正数阈值；页面两位小数只用于展示。先强平、缓冲不足、无有效正数强平价或档位缺失均拒绝生成正式方案。

账户 `canTrade` 必须明确为 true（与 API Key 的交易权限无关；Key 仍必须只读）。报价和标记价的时间与本机相差超过 30 秒时作为过期/不一致数据阻断；最后成交时间可能较早，单独展示。账户档位必须连续有效。官方未明确自定义 `notionalCoef` 是否已应用于返回边界和速算额，因此非 1 系数暂停新建议，不猜测缩放、不代入通用档位。真实账户联调仍待完成。

### 止损模板（任务 07）

“我的止损模板”显示待保存的百分比，以参数摘要识别模板；重复参数只保留一份，可删除。仅持久化层数、止损百分比与原分配比例，不保存币种、方向、绝对价格、预算或资金设置。保存只校验模板本身；预算尚未填写或资金不足也能保存。绝对价按原输入与明确展示的入场参考价换算，截取至最多 8 位小数，小于精度或近远顺序失效时报错；例如参考价 100、原止损 98.09 保存为 1.91%，不是当前合约取整后的 2%。市价采用做多卖一、做空买一，限价采用本单委托价；币种、方向和入场方式仍与已生成方案一致时，可使用该方案标注时间的参考价保存。

### 双层止损与剩余仓位（任务 06）

用户选择单层或双层。双层首次比例 70/30，只编辑近端比例，最终比例自动补足 100%；两层均须为正，两个止损价格/距离不预填。全部初始数量仍按最终止损计算，包括原成本、资金及强平检查，不使用加权距离增加仓位。近端数量向下取到普通/市价数量步长的交集；剩余归最终层，展示取整后价格、距离及实际比例。两价重合、方向不符、近端为零或不满足退出规则时拒绝方案，不自动改单层。最终层采用整仓语义，不套用开仓最小金额或固定数量门槛；近端只减仓退出仍检查数量范围和步长，豁免开仓最小金额。

执行顺序：先随入场设置并确认最终止损覆盖整仓，再补近端固定数量止损；两层均为止损市价、标记价触发、关闭价格保护。最终单在近端退出后仍覆盖全部剩余仓位。核验分别检查两层，不把近端量和整仓量相加；只有最终单时显示近端待补齐。取消、失效、已经执行的条件单不作为待触发保护。

实际入场量变化时，近端按**原输入比例 × 实际累计入场量**重算，而非沿用旧卡取整后的比例。限价余单仍在时不能完成；已撤余单、实际持仓及成交对账后才继续。保持原预算和两个绝对止损价，不通过移动止损或增加预算使核验通过。

双层核验新增固定只读 `GET /fapi/v1/allAlgoOrders`。用历史条件单的 `actualOrderId` 关联普通订单与成交，核对原近端触发条件、只减仓语义、已终止的实际退出订单及成交量；近端市价退出仍在执行时不能完整核验。所有入场成交必须先于部分退出；多开仓单、平后重开、无法关联原近端的手工减仓均不猜测。每笔非零平仓损益必须与 USDT 收支记录对应；手续费从完整成交明细读取，若另有手续费收支记录也须逐笔匹配。缺失手续费、非 USDT 手续费、损益缺失/冲突、重复或截断记录均不能通过。历史仍限定少于 7 天、最多 1000 条，满页拒绝完整核验。

剩余风险复用同一精确成本口径：`max(剩余仓位按原最终止损退出的价格损失 − 本单已实现损益, 0) + 全部已付手续费 + 已付资金费 + 剩余资金费预留 + 剩余仓位退出手续费`。已实现损益保留正负号；原预算不改变，不据此建议加仓。剩余成本按原成交精确均价分配，用整数分子/分母比较，避免提前舍入低估风险；强平缓冲仍用精确入场均价和查询时的实际强平价。资金费收入不扩大预算。单层的非计划部分退出仍返回无法完整核验。

### 成交后单层核验

正式生成通过本机 `POST /api/plan` 刷新、计算并保存原方案到当前登录会话，同时返回供浏览器保存的签名恢复凭证。它不是交易请求，所有 Binance 请求仍为固定白名单 GET。生成期间以交易所时间、空仓/无挂单检查和成交记录确认本单起点；出现交易变化时不建立新方案。恢复时先认证原方案，随后核验仍只提交方案 ID，不能提交替代预算或止损。每个会话保留最多 20 个方案且不自动淘汰，生成响应因输入变化被页面丢弃也不会破坏旧卡；达到上限只暂停新生成，旧方案仍能核验，重新登录后可凭签名记录恢复本单。

返回后点击“返回后刷新核验”或页首刷新按钮，使用 `GET /api/verification?planId=…`。只读查询新增：

| Binance GET 接口 | 用途 |
| --- | --- |
| `/fapi/v1/time`（公共） | 以交易所时间限定起点与查询区间，超过 30 秒时钟差则停止。 |
| `/fapi/v2/positionRisk` | 读取实际均价、数量、逐仓模式、杠杆和当前强平价。 |
| `/fapi/v1/userTrades`、`/fapi/v1/allOrders` | 将本单成交数量、方向、手续费与唯一市价/限价开仓订单对账；限价另比对当前挂单的价格、原数量、累计成交量和状态。 |
| `/fapi/v1/income` | 查询本单区间内资金费支出，识别无法归属的其他收支。 |

同时读取普通挂单、条件挂单、账户权限/模式、当前规则、账户退出费率和标记价。读取前后再次比较持仓与挂单；任一请求失败或两次状态不一致，本次不能通过。REST 读取不是交易所原子快照，只能排除已观察到的不一致，不宣称持续监测。完整查询共用 10 秒超时。

业务入口 `verifyPosition(config, plan)` 的本期边界：

- 本单从已确认空仓开始，只自动关联一张同方向市价或原价格的普通 GTC 限价开仓订单；允许同一订单多次成交。订单执行量、成交明细及实际仓位必须一致，均价仅容忍交易所 8 位小数展示的一个最小单位。多张开仓单、撤单重挂、重新开仓、部分平仓、重复/缺失记录及无法换算的非 USDT 手续费均返回“无法完整核验”。完整平仓的成交链能与空仓对账时显示“已结束”，无成交的空仓显示“待成交”；限价零成交且已确认撤单、无其他挂单时显示“已结束 · 未成交已撤销”。这些状态都不是核验通过。
- 限价部分成交显示累计成交和逐张入场余单数量。余单仍在时必须由用户先在 Binance 撤销；只有历史的终止状态与当前挂单查询一致、成交明细与实际仓位对账后，才可能通过预算、强平缓冲及止损覆盖检查。不把原主单数量当成实际仓位。保护/平仓先执行而入场余单仍存在时明确提示余单可继续成交并重新形成仓位，不能完成流程；不凭已消失的条件单猜测具体保护归属。已实现损益收支须能对应本单成交；无法归属的支出或平仓后再次成交返回“无法完整核验”。
- 原预算、绝对止损和滑点固定。重新计算：`实际数量 × max(0, 有方向的实际均价与不利退出估值之差) + 已付手续费 + 已付资金费 + 剩余资金费预留 + 退出手续费`。风险与缓冲比较使用已对账成交的精确价格数量乘积，不让交易所展示均价的取整降低损失或扩大缓冲。退出费率取本次账户查询；剩余资金费为 `max(原预留 − 已付资金费支出, 0)`，收入不扩大风险预算。超出原预留的实际支出完整计入。亏损/超额展示向上取到 8 位小数。
- 缓冲按实际均价与当前强平价计算有方向间距，不使用开仓前强平估值。实际杠杆低于原值可继续检查，高于原值需处理；缺失当前强平价不能通过。
- 只接受一张有效单层保护：平仓方向正确、原触发价、标记价、止损市价、关闭价格保护。整仓退出不构造固定数量；等效固定数量退出必须只减仓且严格等于当前数量，并满足当前普通/市价数量规则，不套用开仓最小名义价值。取消、失效、到期或已触发/已执行订单不算保护；未成交入场余单阻止完成。
- 历史查询限定一个少于 7 天的区间，每类最多 1000 条；满页就明确停止完整核验，不把截断记录当作完整历史。更长区间、分页、多单执行及部分平仓损益处理留待相应后续流程。

修改输入、切换模拟场景或开始新查询立即撤销当前通过状态。原方案和上次查询时间保留；恢复原输入并重新查询才能核验旧卡。止损错误会给出具体应有参数，风险与缓冲不足会给出差额；不提供缺少减仓成交成本支撑的精确修正数量，工具不执行交易。
