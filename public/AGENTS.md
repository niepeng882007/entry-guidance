# 前端样式修改

项目范围、模块边界及事实来源见 [公共索引](../docs/index.md)。

修改 HTML、CSS 或前端渲染时遵循本文件。目标是让样式归属可搜索、修改影响可预测；保持原生 HTML/CSS/JS，当前不引入组件库或构建工具。

## 修改入口

- 主题与重复设计值：修改 `style.css` 顶部 `:root` 的变量。颜色按用途命名；`--space-*` 的数字标识现有间距尺度。仅使用一次的布局尺寸保留在所属组件。
- 组件：在 `style.css` 搜索对应类名。基础规则、变体、状态和 `560px` 手机断点放在同一组件段落；共用部件的变体放回该部件，例如按钮放在 Buttons、金额放在 Amount。
- 页面结构：`account.html` 和 `login.html` 显式引用样式类。用 `组件__部件` 表达归属，`组件--变体` 表达差异；变体与基础类同时使用，如 `class="button button--text"`。

## 边界

- 新组件先复用已有按钮、表单、金额、明细与提示样式；确有差异时增加具名变体。页面专属规则留在页面组件段落。
- 样式使用类名，ID 用于 JS 定位、表单标签和 ARIA 关联。全局规则只承担基础排版、焦点和隐藏语义；组件内部最多一层后代关系，避免依赖祖先页面或标签嵌套。
- `hidden`、`data-state`、`data-current` 是 JS 驱动的状态，CSS 消费状态。保留 `[hidden]` 的唯一 `!important`，以免 flex/grid 显示已失效的结果。
- 保留原生 input/select/button/details 的类型、属性和事件。`app.js` 依赖 ID、原生控件接口及 `status.closest('section')`；改变这些契约时先检查调用方。
- 保留单个 `style.css` 入口；服务端按白名单读取静态文件，拆文件需要同步修改 `src/server.ts`。纯样式改动不应改动业务计算。

## 验证

样式重构需对照修改前的登录页、表单、错误状态、草稿、有效/失效开仓卡及核验明细；覆盖 320px、390px、1280px，检查横向溢出、键盘焦点、隐藏/禁用状态和折叠内容。运行 `package.json` 中现有类型检查与测试；浏览器验证使用模拟数据。服务端在启动时读取静态文件，修改后重启验证服务。
