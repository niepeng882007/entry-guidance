# 26: 旧账本、浏览器状态与本单迁移演练

**What to build:** 原工具使用者能用一次受控迁移将旧账本和可信本单带入明确的新账号，验证数据一致且不会错误认领。

**Blocked by:** 10 私有偏好、模板与手机返回恢复；24 注销、完整清理与独立撤销记录。

**Status:** ready-for-agent

**规格关联：**用户故事 32、72、80；实现决策 13、19、21、23、24。

- [ ] 使用合成旧 SQLite、旧 v1 备份和浏览器数据，迁入原拥有者指定且验证同 UID 的产品用户，不能按最先注册或自报 UID 认领。
- [ ] 逐类核对数量、身份、金额字符串、净盈亏、方案关联、笔记版本及缺口，旧 v1 转换为当前有效归属的 v2。
- [ ] 当前本单在原环境验证 recovery 凭证再受控登记，原预算和止损不变；普通备份方案不获信任，旧密码和验签配置不长期上云。
- [ ] 无可信 UID/签名的本单阻止该账户切换，明确先在旧工具完成，不重新生成扩大预算。
- [ ] 跨 origin 的偏好、模板和本单通过原用户明确操作迁移，不能假设新站能读取旧站 localStorage。
- [ ] 演练新写入前撤销切换和新写入后只回退兼容 Neon 应用；所有平台迁移副本纳入清理，实际旧库不在本票操作范围。
