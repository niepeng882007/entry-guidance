# 23: 解绑、只读归档与换账户

**What to build:** 用户可解绑当前账户、保留原 UID 的只读历史，并绑定新账户；重新验证原 UID 后能恢复原账本功能。

**Blocked by:** 14 订单主列表与完整交易关联；22 带归属证明的备份与事务恢复。

**Status:** ready-for-agent

**规格关联：**用户故事 13、15、73、74、75；实现决策 5、6、8、16、21。

- [ ] 解绑立即撤销平台凭据、相关任务执行权和后续外部调用，迟到写入不能重新激活旧作用域。
- [ ] 归档历史、笔记、既有报告、统计及导出仅对原用户可见；新增笔记、AI、同步和恢复写入均被服务端拒绝。
- [ ] 归档期间保留 UID 占位，同一用户最多一个活跃绑定；新 UID 新建作用域且不转移旧数据。
- [ ] 同 UID 重绑重新验证只读权限并增加授权代次，恢复原账本的正常功能。
- [ ] Binance Key 临时失效不等同解绑，仍保留原本地笔记及独立有效模型能力。
- [ ] 页面、浏览器缓存、后台任务和恢复入口的状态切换以两个账户/两个用户验收。
