# 05: 资产快照与多用户读取协调

**What to build:** 用户能查看自己的资产快照、查询时点和冷却信息，资产页保持 30 秒节奏，并提供开仓复用的 3 秒摘要。

**Blocked by:** 04 Binance 只读绑定与同账户换 Key。

**Status:** ready-for-agent

**规格关联：**用户故事 35、36、37、38；实现决策 14、15、21。

- [ ] 资产明细和查询信息按现有交互展示，每轮完成后等待 30 秒；摘要保持原 3 秒更新边界。
- [ ] 两用户并发访问相同上游地址不串用签名、响应、缓存或权限错误。
- [ ] 按出口协调权重和限流冷却，前台优先于归档；权限失败只影响对应绑定，交接不得清零上游冷却。
- [ ] 隐藏、离线、失效、超时和迟到响应按现有语义处理，旧数据不能伪装成刚查询的结果。
- [ ] 用替换 transport、HTTP 及两用户浏览器验证，保留后端持仓和普通/条件订单读取能力但不恢复已移除的资产页内容。
