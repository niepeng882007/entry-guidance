# 06: 双层止损规划与剩余仓位核验

**What to build:** 用户选择双层止损、填写两个止损距离并调整初始 70/30 比例，得到按最终止损控制仓位的开仓卡。执行时先保证最终止损覆盖，再设置近端部分止损；近端退出后能核验实际剩余仓位、整笔风险与最终保护。

**Blocked by:** 04 — 成交后单层止损核验。

**Status:** implemented-locally — pending iOS App validation

- [x] 单层与双层由用户选择；双层初始比例为 70/30，可调整且两层比例均为正、合计 100%，两个止损条件由用户输入，不预填普适距离。
- [x] 双层全部数量按最终止损和已约定成本反推，遵循既有最终止损定仓 ADR；不得使用加权距离扩大初始仓位。理论预算 20、最终距离 1.6%、费用/滑点为零时，名义仓位为 1250，示例不成为产品默认值。
- [x] 多空的近远价格顺序正确；止损取整后展示实际价格和距离。近端数量向下取到适用步长，剩余归最终止损，并显示实际比例。
- [x] 两层价格取整后重合、近端数量为零或违反适用退出规则时，拒绝当前双层方案并说明原因；不自动增仓、改单层或放宽预算。
- [x] 两层均为止损市价、标记价触发、关闭价格保护，具有正确平仓语义；固定数量退出按适用数量规则处理，整仓保护不重复套用开仓最小金额门槛。
- [x] 开仓卡展示两层触发价、退出量/比例及设置顺序；先确保整仓有最终止损保护，再补近端部分止损。仅最终止损已就位时，显示仍待补齐近端计划，不能声称双层完全符合。
- [ ] 对当前 Binance 目标手机入口验证开仓附带最终止损、近端部分止损及远端整仓保护的设置和并存行为；记录证据与限制。不能仅凭 API 字段宣布整套界面流程成立，不擅自在真实账户下单验证。
- [x] 核验分别检查近端部分退出与远端剩余保护，不将整仓保护和部分止损的重叠数量相加；取消、失效或已经执行的委托不继续计为待触发保护。
- [x] 近端已成交时，根据实际剩余仓位和可归属本单的成交、已实现损益及费用，核验整笔预算、当前强平缓冲和最终止损覆盖；无法归属时显示无法完整核验，不只计算剩余敞口冒充整笔风险。
- [x] 沿用原预算和原绝对止损价处理偏差，显示需补齐或修正的内容；仍有入场余单时不完成流程。与已存在的入场方式共用规则，不另建一套独立风险模型。
- [x] 通过业务入口覆盖两层都有效、只存在最终止损、近端已执行、覆盖重叠、远端被取消、剩余数量变化、费用归属缺失及分层取整失败，并完成手机双层输入到核验的可见场景。
