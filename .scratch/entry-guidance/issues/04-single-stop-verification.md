# 04: 成交后单层止损核验

**What to build:** 用户持有正式单层市价方案，到 Binance 手动执行后返回刷新，工具读取实际仓位与挂单，核验本单风险、当前强平缓冲和止损覆盖。结果指出偏差与修正建议，只有检查通过才标记本次流程完成。

**Blocked by:** 03 — 资金与强平校验后的正式开仓卡。

**Status:** done

- [x] 返回刷新时同时读取实际持仓、普通挂单和条件挂单；明确实际均价、数量、当前强平价及查询时间，不能只查普通挂单就判断止损不存在。
- [x] 将实际状态与原方案关联，核对币种、方向、逐仓/单向模式、实际杠杆及本单起点；无法可靠关联时显示无法完整核验，不猜测订单归属。
- [x] 成交后沿用原 USDT 预算和原绝对止损价，以实际均价、数量、可归属的已付成本及剩余退出假设重新核算风险；不得抬高预算或将止损向更远处平移以通过检查。
- [x] 使用当前强平价及实际均价核对用户最低强平缓冲；区分开仓前估值和当前持仓值，数据缺失或缓冲不足不能通过。
- [x] 单层止损必须有效，平仓方向、数量覆盖、触发价、标记价依据、止损市价类型和关闭价格保护均符合方案，具有正确整仓/只减仓语义。
- [x] 固定数量退出与整仓平仓分别处理；不误套开仓最小名义价值限制，也不把只减仓豁免扩大为所有数量规则豁免。失效、已取消或已执行的订单不计为有效保护。
- [x] 出现未成交入场余单时不完成流程，明确提示用户处理；存在尚未支持或无法可靠计算的部分平仓归属时，返回无法完整核验，不输出错误通过状态。
- [x] 预算超额、止损缺失或参数不匹配时显示“需处理”、具体差额/缺项和有数据支撑的修正建议；用户在 Binance 处理后刷新复核，工具不执行修正交易。
- [x] 无实际仓位时按事实显示待成交或已结束，不能将空仓当作止损通过。已核验结果带查询时间，方案修改或新查询发现变化后重新检查。
- [x] 超时、权限缺失、部分查询失败或不一致快照时撤销当前通过状态，保留原方案及上次时间，不静默切换成手填或模拟值。
- [x] 从核验的公开业务入口覆盖正确单层保护、缺单、错误方向/数量/触发条件、取消状态、预算超额、强平不足、空仓及无法关联等场景；用模拟/脱敏响应演示“刷新—需处理—处理后通过”，不以真实下单测试。

验收记录（2026-09-21）：用户确认唯一市价订单自动关联、已付资金费消耗原预留、降低实际杠杆可继续核验，以及等量合法只减仓止损可作为等效保护。`npm run typecheck` 和 `npm test`（136 tests）通过；浏览器完成模拟需处理、修正后通过、查询失败撤销及恢复输入后重查，窄屏与桌面未见横向溢出。

Standards / Spec 审查发现并修复生成响应丢弃导致旧方案失联、展示均价取整导致预算错误通过两项问题，均补充回归检查，复审无遗留。真实账户只读联调尚未完成；部分平仓完整损益核算与跨关闭恢复保留后续工单，具体接口、口径和边界见 README。
