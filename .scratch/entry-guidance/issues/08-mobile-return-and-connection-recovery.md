# 08: 切换 App 与断线后的流程恢复

**What to build:** 用户在手机上切换到 Binance、返回网页或遇到断线后，能够保留当前计划、看清旧结果的时效并继续刷新核验。恢复流程覆盖市价/限价及单双层方案，避免重新填写，也避免迟到或不完整数据恢复错误的通过状态。

**Blocked by:** 05 — 限价入场与部分成交处理；06 — 双层止损规划与剩余仓位核验。

**Status:** implemented — 本地模拟验收完成；实体手机与真实账户联调边界见下文。

- [x] 切换 App 后返回保留本次计划、已固定预算、绝对止损条件及用户输入；刷新当前账户、行情、持仓和普通/条件挂单后再判断，不以保留的页面状态证明仍符合计划。
- [x] 恢复流程适用于市价、限价、单层、双层及近端已退出的剩余仓位；使用已有业务入口，不为恢复建立另一套计算规则。
- [x] 明确区分草稿、待成交、待核验、需处理、已核验和已结束；已核验带查询时间，空仓不直接成为核验通过。
- [x] 断线、超时、权限问题、登录过期或部分读取失败时，保留计划及上次查询时间，取消当前通过状态并暂停新可执行建议；旧止损参数仍可查看，不静默转为手填或模拟数据。
- [x] 重新连接或重新登录后，用户能继续本次流程并重新查询；结果仍受原预算约束，只有数据完整且所有适用检查通过才能重新标记完成。
- [x] 用户修改计划期间到达的旧请求结果不能覆盖新输入或恢复旧的通过状态；来自明显不一致查询时点的数据不得拼成已核验结果。
- [x] 无法确定已有计划与实际仓位的对应关系时，显示无法完整核验及缺项，不自动为已有仓位创建新的扩大预算方案。
- [x] 模拟数据来源始终清楚，不能恢复为真实账户建议；页面关闭期间不声称持续监控，不引入后台交易、推送或云同步。
- [x] 手机窄屏、软键盘展开、错误与恢复状态下无横向滚动，单位和内联错误明确，复制/刷新可触达且具有基本无障碍支持；桌面交互保持可用。
- [x] 以受控响应演示返回页面、查询超时后重试、部分失败、登录过期、迟到响应及旧方案与新输入竞态；通过公开业务结果与少量完整手机浏览器场景断言行为。
- [x] 本地验收过程中只读真实账户；涉及订单变化的场景使用模拟/脱敏数据或另行明确的模拟环境。完成此任务不包含服务器采购、域名配置或公网部署。

验收说明：用户确认同一浏览器保留本单直到显式新单/清除，支持关闭、重登和服务重启，返回或联网自动查询。HTTP 测试与手机浏览器受控响应覆盖恢复和竞态；手机布局采用 320px、390px、320×330 键盘占位视口，桌面为 1280px。实际 iOS 软键盘、切换 Binance App 与真实账户只读联调尚未验收，不把视口/事件模拟当作实体设备验收。本次没有读取真实账户或执行交易、部署。详细场景见 README“本单恢复（任务 08）”。
