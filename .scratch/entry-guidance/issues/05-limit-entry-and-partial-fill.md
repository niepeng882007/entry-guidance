# 05: 限价入场与部分成交处理

**What to build:** 用户可选择限价入场，基于指定价格生成带止损的开仓方案，并在挂单、部分成交及人工撤余单后得到正确核验。限价的计算与成交状态贯穿现有开仓卡及手机返回流程，不让止损后继续成交的余单被忽略。

**Blocked by:** 04 — 成交后单层止损核验。

**Status:** ready-for-agent

- [ ] 增加市价/限价选择并记住上次选择；仅限价要求委托价，切换方式时旧计算和通过状态失效并重算。
- [ ] 限价入场使用用户委托价，输入不符合价格步长时明确提示修正，不静默改价；入场假设不突破其限价，止损退出仍按不利市价滑点估算。
- [ ] 计划阶段普通限价单仍按账户 taker 费率预留，不自动假定 maker；限价开仓资金、开仓浮亏及强平估算按当前官方适用规则处理。
- [ ] 等待成交期间显示挂单和待成交状态，不能把有委托无持仓当作止损已核验。实际成交后读取均价、数量和对应成本，保留原风险预算与止损价。
- [ ] 部分成交且仍有入场余单时，明确显示已成交量和待撤余单，要求用户先在 Binance 撤销余单；不由工具代撤，也不假定保护单触发会撤掉余单。
- [ ] 余单撤销并经刷新确认后，按真实持仓数量与已付成本重新检查预算、强平缓冲和止损覆盖；不足或超额时给出具体问题，不默认原主单数量等于实际仓位。
- [ ] 保护单先执行而入场余单仍存在时，不标记流程完成，明确指出重新形成仓位的可能路径；相关成交或损益归属不清时显示无法完整核验。
- [ ] 市价路径的风险、资金、只读权限和错误处理保持可用；关键读取失败同样不能得到正式建议或核验通过。
- [ ] 从业务入口覆盖未成交、全部成交、多次部分成交、人工撤余单后复核、保护先执行及余单仍在的情形，断言实际结果而非内部调用次数；用手机完整演示其中一条部分成交流程。
