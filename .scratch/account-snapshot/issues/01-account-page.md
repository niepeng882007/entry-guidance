# 01: 独立资产快照页

**What to build:** 使用者登录后能直接打开独立账户快照页，查看当前普通 USDT 单资产账户的权益、可用余额、未实现盈亏和资金占用明细，并从工作台进入、返回或退出登录。页面正常前台每 3 秒刷新，支持手动刷新和明确的失败状态；原工作台的账户摘要与刷新继续可用。页面沿用黑白简洁风格，在手机与桌面均可独立演示和验收。

**Blocked by:** None (can start immediately).

**Status:** implemented — 自动与模拟浏览器验收通过；实体手机、真实账户未验收

- [x] 提供受既有登录保护的独立页面和只读资产读取入口；工作台提供入口，账户页可返回工作台或退出登录。页面、数据与构建资源的访问边界一致。
- [x] 原工作台的账户权益、可用余额、钱包余额、未实现盈亏、成功查询时间和最近尝试时间全部保留，正常前台每 3 秒刷新行为不改变。
- [x] 新页面突出账户权益、可用余额与未实现盈亏；展开查看钱包余额、持仓初始保证金、委托初始保证金、维持保证金、可转出额和查询信息。
- [x] 权益沿用 USDT 钱包余额加未实现盈亏的口径；可用余额采用交易所返回值，不重复扣除占款。所有金额使用既有十进制定点入口，保持精度和明确单位。
- [x] 页面首次读取、正常 3 秒刷新和手动刷新可用；已有查询忙时不堆积请求。隐藏或离线时暂停，返回与联网恢复立即查询，取消或迟到响应不覆盖当前状态。
- [x] 查询失败保留旧值及原成功时间并明确标过期；没有成功数据时显示等待或失败，不伪装为零余额。未知字段与不适用字段分开表达。
- [x] 来源明确区分模拟与 Binance；会话失效停止查询并提供重新登录入口，读取失败不静默改用模拟数据。
- [x] 继续使用后端固定白名单 GET，校验专用只读权限和普通 USDT 单资产口径；不因账户已有全仓、双向持仓而拒绝资产观察。多资产与组合保证金账户仍拒绝。
- [x] 凭据不进入前端、浏览器存储或错误输出；非法方法、路径及参数不能成为任意签名代理，生产 CSP 不被放宽。
- [x] 如需复用已有账户检查与解析，在本任务中先做保持既有契约的最小兼容提取，再接入新页面；不扩大为无关重构。
- [x] 黑白色板、系统字体、按钮、金额、明细和焦点规则复用现有样式；在 320px、390px 与 1280px 检查金额、单位、展开内容及键盘焦点，页面无横向溢出。
- [x] 从公开 HTTP 入口替换 Binance 外部响应验证金额、权限、登录、失败与脱敏；通过生产构建浏览器验证导航和刷新。测试不读取真实凭据，也不进行交易。

## 实施与验收记录

- 2026-10-13：独立页面 `/account` 与受保护的固定 GET `/api/account/assets` 已实现；工作台提供详情入口，原账户摘要与刷新保持。
- 用户确认：核心余额继续严格验证；新增明细缺失显示“未知 · 未返回”，非法值使整次读取失败，保留旧值与原成功时间。
- 公开 HTTP 与生产浏览器覆盖金额、权限、账户口径、脱敏、访问保护、刷新取消、异常恢复、会话失效及三个指定视口；仅使用模拟数据与替换的 Binance 响应。
- `pnpm check` 通过，50 个 Chromium / WebKit 浏览器用例通过；截图已目视检查，实体手机和真实账户仍待验收。
