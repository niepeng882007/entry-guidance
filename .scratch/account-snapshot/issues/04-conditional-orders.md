# 04: 条件委托与统一委托浏览

**What to build:** 使用者在同一活跃委托浏览区查看普通挂单与止盈止损等条件挂单，按需展开触发参数、只减仓、整仓退出和价格保护信息。固定数量与整仓语义清楚区分，普通委托和条件委托各自的读取时间与失败状态可见；页面列出事实，不自动给出止损已保护或核验通过结论。

**Blocked by:** 03 — 普通活跃委托详情。

**Status:** implemented — 本地模拟验收完成，实体手机与真实账户待验收

- [x] 在已有普通活跃委托浏览区加入全账户条件活跃委托，清楚区分普通与条件类型；不局限于当前方案的止损单。
- [x] 条件委托主览显示标的、买卖方向、持仓方向、类型、适用的委托价或触发价、固定数量或整仓退出语义及状态。
- [x] 展开显示条件委托标识、可读取到的创建与更新时间、触发依据、只减仓、整仓退出、价格保护及适用的有效方式；不适用与未知设置分别表达。
- [x] 整仓退出条件单不得显示成零数量或凭空推定固定数量；只有上游提供足够证据时才显示已执行量或剩余量，不能为条件单默认补零。
- [x] 标记价触发、最新成交价触发及其他有效触发依据按事实命名，不将触发价当成保证成交价，不将未知触发依据默认为标记价。
- [x] 普通与条件委托的标识不会因数值相同而相互覆盖；同标的双向委托可明确区分，数量与标识不丢失精度。
- [x] 普通与条件委托各自正常前台每 3 秒刷新并保留对应成功时间；一类读取失败时另一类仍可显示成功数据，过期记录和当前记录不混淆，汇总数量不冒充全部数据已确认。
- [x] 统一浏览和标的筛选准确区分结果数量与全账户委托数量，保留展开与焦点；成功无委托与部分委托来源尚未确认分别表达。
- [x] 条件委托新增、变化或移除后成功列表准确更新；移除不推断为触发、成交或撤销。止损委托存在不自动显示已保护、风险通过或止损核验通过。
- [x] 手机与桌面可完整阅读长标识和触发参数，继续使用黑白层级和轻微动效；样式与普通委托一致，尊重减少动态效果偏好。
- [x] 以公开读取入口和生产浏览器验证固定数量只减仓、整仓退出、止盈止损类型、触发依据、价格保护、同标的双向、标识碰撞、分项失败及记录移除；无真实资金或账户写操作。


## 实施与验证记录（2026-10-14）

- 增加登录保护的固定 GET `/api/account/conditional-orders`，沿用只读权限和普通 USDT 单资产口径；全账户条件读取不要求空仓或关联方案。
- 普通与条件委托在同一区域混排、共用标的筛选，按标的、持仓方向、来源及精确标识稳定排序。键包含来源，普通 orderId 与条件 algoId 相同也不会覆盖。
- 固定数量、整仓退出与未知设置分别表达；整仓返回的零数量不展示为固定零。已执行量只保留上游证据，剩余量仅在上游返回或固定数量与已执行量足以计算时展示。
- 主览与展开覆盖止损、止盈、追踪止损、触发/激活价、回调比例、触发依据、只减仓、价格保护、有效方式、标识与时间；未知触发依据保留原值，缺失不默认标记价。
- 每类委托有独立成功时间、错误及过期状态；成功数据与旧列表按记录标注，汇总在任一来源未确认时仅称已知列表合计。刷新、切换与筛选保留仍在列表中的展开和焦点，移除不推断历史结果。
- 公开 HTTP 测试覆盖长整数 JSON 标识、全账户范围、数量证据、字段缺失/无效、追踪参数、只读权限、口径拒绝、错误脱敏与方法/参数边界。生产 Chromium / WebKit 覆盖字段展示、标识碰撞、分项失败/恢复、记录变化、取消迟到响应、离线/隐藏/返回、401 停止及 320/390/1280px 和减少动态效果。
- 接口、字段与权重于 2026-10-14 核对 [Binance 官方交易文档](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)；全账户条件委托权重 40，普通与条件每三秒各读取一次合计约 1600 权重/分钟，尚不含账户/行情及其他页面。限流与跨页面协调继续由任务 05 实施；本次模拟不能证明真实账户额度可持续。
