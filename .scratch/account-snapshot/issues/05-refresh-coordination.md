# 05: 全账户刷新协调与异常恢复

**What to build:** 使用者持续浏览完整账户页时，资产、持仓、普通委托、条件委托及辅助行情按正常前台 3 秒目标更新；工作台、详情页和多标签页共享可合并的读取，限流或持续失败时明确退避。分项新旧状态、失败原因和查询时间清楚，恢复后可继续浏览，原开仓与核验规则保持。完成完整页面的交互打磨与整体回归验收。

**Blocked by:** 02 — 全部当前持仓与行情详情；04 — 条件委托与统一委托浏览。

**Status:** implemented — 自动与模拟浏览器验收完成；实体手机、真实账户待验收

- [x] 集成资产、持仓、普通委托、条件委托和辅助行情的刷新，正常前台每 3 秒更新全部信息；手动刷新、返回页面或恢复联网不造成重复并发或查询堆积。
- [x] 工作台摘要、账户详情与多标签页的重复读取可合并；各访问者仍受登录与账户口径检查，真实与模拟来源不混用，旧缓存不冒充新查询结果。
- [x] 核实实际交易所请求额度与全账户读取成本；按照上游限流要求退避，持续失败时降低重复尝试。多个访问者及手动刷新不能绕过有效退避，界面显示原因与对应时间。
- [x] 资产、持仓、普通委托、条件委托及辅助行情各自保留成功时间和最近尝试状态；分项失败不覆盖可继续更新的成功分项，不用新总时间覆盖旧分项时间。
- [x] 权限、账户口径、来源或必要时间无法确认时撤销相应当前有效状态；会话失效停止读取。没有成功数据时不显示虚假的零余额、空仓或无委托。
- [x] 断网、隐藏、离开或关闭时暂停并取消页面待完成请求；返回与联网恢复立即重新查询，取消及迟到响应不能覆盖较新状态。共享读取不产生无访问者的后台持续监控。
- [x] 刷新与失败恢复保留用户的持仓或委托视图、标的筛选、稳定顺序、仍存在记录的展开状态和焦点；成功移除的记录不继续冒充当前有效记录。
- [x] 完整页面明确区分所有记录数量、筛选结果数量、当前与过期记录，兼容空状态、部分数据可用和全体失败；高频更新不闪动整页或打断阅读。
- [x] 原工作台全部账户信息与刷新继续可用；原输入、草稿、开仓卡、复制、恢复和核验行为保持。资金变化或读取失败仍按原规则撤销当前状态，不改写冻结预算与绝对止损，不自动恢复通过。
- [x] 原正式方案与核验继续保有其完整查询语义；不得以过期或仅部分成功的账户详情缓存生成可执行建议，也不扩大全仓、双向开仓或核验支持范围。
- [x] 在 320px、390px 与 1280px 完成资产、持仓、普通与条件委托、展开明细、错误恢复、键盘焦点及减少动态效果的综合浏览器验收；长标识和高精度数值无横向溢出。
- [x] 从公开 HTTP 入口、现有 Binance 外部响应替换和生产浏览器验证多访问者读取合并、受控 3 秒时钟、忙时跳过、取消、迟到响应、各分项失败、限流退避、断网恢复和会话失效。
- [x] 运行项目既有完整检查，更新使用与验收记录；分别记录模拟、浏览器、实体手机和真实账户状态，不将尚未完成的实机或实连验收记为通过。


## 实施与验收记录（2026-10-14）

- 后端共享读取按当前服务实例及固定账户/来源隔离，摘要与资产共享原账户查询；持仓、普通及条件委托分别保留成功结果。正常前台三秒目标，成功读取最多复用 2.9 秒，保留原查询时间并明确复用；只合并正在进行的权限、账户口径及合约元数据读取。没有定时后台任务。
- 每个 HTTP 访问者先验证会话，返回前再次核验；一个访问者取消不影响其他等待者，最后访问者离开取消共享上游，取消或失效轮次不能进入有效缓存。全轮十秒超时。
- 连续失败采用 3、6、12、24、48、最多 60 秒退避，成功重置；手动刷新、多会话不能绕过。429/418 共享禁入期优先取 Retry-After/封禁截止，缺失时分别等待 60 秒/3 天；响应只输出脱敏原因、实际尝试和下次允许读取时间。
- 读取现有 exchangeInfo 的 REQUEST_WEIGHT 实际额度及权重头，按已核对的账户观察读取权重预留额度，窗口不足时暂停。ticker V2 的一分钟用量头按官方说明忽略。实际 IP 的其他调用与未预估的严格查询仍以交易所权重头及429约束，不能承诺限流期三秒取得新数据。
- 各分项保留成功时间和实际尝试；辅助行情独立表达成功/失败与退避。普通失败只撤销对应分项；权限、账户口径或来源未确认撤销全部当前状态。旧列表数量标为上次全账户，成功移除仍更新列表，不推断成交/撤单。
- 完整行情、正式方案及核验使用独立完整读取，仅遵循共同上游禁入期，不借用账户观察缓存。冻结预算、绝对止损与既有支持范围保持。
- HTTP 通过现有 Binance transport 验证多访问者全分项合并、查询时间、取消、连续失败、429/418、运行时额度、会话与严格查询隔离。生产 Chromium/WebKit 覆盖受控三秒时钟、忙时跳过、迟到响应、断网恢复、分项/全部失败、会话失效和320/390/1280px、长值、焦点、展开与减少动态效果。
- `pnpm check` 通过：232项Node测试、122项Chromium/WebKit用例；账户、持仓与统一委托截图已目视检查。双轴审查结果在交付后更新；实体手机、真实 Binance 只读持续刷新额度与真实账户联调尚未验收。没有执行账户写操作或生产部署。
