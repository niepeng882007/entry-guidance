# 11: 筛选范围批量 LLM 分析

**What to build:** 使用者主动对当前筛选范围最多 100 笔交易发起批量复盘，结合全部有效统计及逐笔证据回顾表现规律和执行问题。数据过大时完整分段再综合，每条结论能追溯到交易或统计分组，报告不会把部分覆盖冒充全范围完成。

**Blocked by:** 10 — 单笔 LLM 完整上下文分析。

**Status:** done

- [x] 当前筛选范围可以主动发起批量分析，使用全范围而非当前列表页；超过 100 笔时提示缩小范围，不静默取前 100 笔，也不限制用户发起分析的次数。
- [x] 批量表现结论仅采用对应数据完整的已结束交易，提供有效样本、排除数量和原因；当前选择范围与有效分析范围分别清楚展示。
- [x] 包含全部有效统计、逐笔相关成交与订单、费用、原方案和核验、标签、允许的笔记及带时点的行情，冻结本次范围和证据。
- [x] 复用已有长任务、报告、取消、用量和恢复能力；全量分段后综合，逐段记录交易及时间覆盖，任何遗漏、失败或截断都不产生完整报告状态。
- [x] 最终报告明确综合阶段引用分段结果，各结论关联具体交易或统计分组；小样本规律、缺少原计划的交易及操作动机保持相应证据边界。
- [x] 后台归档、编辑标签或笔记及切换筛选不修改运行中范围；旧报告保留其范围和时点，重复查看不会重新调用模型。
- [x] 模型推测的风格分类单独展示，经用户确认后才成为个人标签，不把推测直接写成交易事实。
- [x] 用户主动选择继续、重试或重新生成，不自动重复收费；无固定次数限制，未知用量和可能已发生的上游费用如实表达。
- [x] 验证跨分页范围、100 笔边界、多币种、缺项排除、全量覆盖、分段失败、取消、运行中数据变化与证据引用；模型使用受控响应，HTTP 和浏览器流程均可独立验收。


## 已确认实施边界

- 自 main `f5d176b` 新建 `codex/batch-trade-analysis` worktree；沿用现有依赖与 SQLite 表，无账本迁移。
- 100 笔按筛选命中总数计算，与分页及有效样本数无关；排除样本保留逐笔证据，不参与对应表现规律。
- 默认不发送笔记，只冻结当前归属的已保存版本；行情保留全部已归档周期、两个来源原值，不主动补查。
- 继续使用原证据与已完成分段；重试/重新生成冻结新证据，旧任务与报告保留。
- 风格建议独立展示，经用户进入详情手动编辑标签与保存笔记才成为个人标签。
- TDD 公共边界为任务 HTTP、持久账本接口与生产构建浏览器；未连接真实 Binance 或模型、未读取真实密钥、未产生调用费用。
