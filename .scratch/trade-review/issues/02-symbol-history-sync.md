# 02: 单币种真实历史同步

**What to build:** 使用者选择一个 USDT 永续合约并主动同步最近 3 个月的真实历史，看到读取进度、可确认的完整交易和不完整记录。订单、成交及费用原始证据长期保存，失败或分页未完成时清楚展示缺口，可再次发起补查。

**Blocked by:** 01 — 复盘入口与单笔持久归档。

**Status:** ready-for-agent

- [ ] 提供选择合约、开始同步、查看进度和结果的完整流程；仅使用后端固定白名单 GET，账户设置及交易操作仍由用户在 Binance 执行。
- [ ] 同步前验证只读权限和账户身份；同账户换密钥沿用归档，不同账户及真实或模拟模式隔离，身份无法确认时保留旧账本并暂停新增归档。
- [ ] 分批读取最近 3 个月的成交、普通订单、条件订单及收入流水，遵守各来源的当前时间窗口和分页规则；达到单页上限不代表全部读取完成。
- [ ] 读取和保留可关联的强制订单证据以识别强平或 ADL；普通市价、限价类型不足以确认退出原因，缺失订单元数据显示未知。
- [ ] 先让单向单次入场与完整退出的交易可查看，其他暂不支持的复杂成交链保留为不完整记录，待交易周期归并任务扩展。
- [ ] 起点以完整成交链和可对账持仓证据确定，不假设同步边界时账户空仓；缺少可靠起点、交易期间证据或退出时点时说明原因。
- [ ] 手续费和已实现盈亏按来源关联，资金费计入正负收支；非 USDT 费用保留原资产数额，换算或归属不可靠时净盈亏待确认。
- [ ] 原始记录、分页进度、完成区间和失败状态可持久恢复；重复同步幂等，失败或未完成的分页不推进完整性状态。
- [ ] 页面显示查询范围、最后成功时间、进度及缺失项；迟到响应、会话失效和失败不把旧结果标成最新或完整，不静默改用模拟数据。
- [ ] 从公开入口用替换的 Binance 响应验证多页、时间分片、缺少起点、权限或身份失败、限流、非 USDT 费用和重启补查，并验证浏览器同步状态。
