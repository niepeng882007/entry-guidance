# 01: 复盘入口与单笔持久归档

**What to build:** 使用者登录后能进入复盘，在明确标注的演示模式中查看一笔从空仓到再次空仓的完整交易，展开订单、逐笔成交和净盈亏分项。交易存入服务端长期账本，退出、清除当前本单及重启后仍可查看，形成可独立验收的最小复盘流程。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 提供受既有登录保护的复盘入口、交易列表与单笔详情；演示模式贯通账本、业务接口与页面，真实模式在尚未同步时明确显示无归档或未同步。
- [ ] 使用受控单向开仓、平仓成交链演示完整交易，详情保留订单、逐笔成交、币种、方向、时间、数量和价格的关联，不以订单或成交条数代替交易笔数。
- [ ] 展示已实现盈亏、手续费、资金费净收支与复盘净盈亏；演示数据包括资金费收入和支出，金额使用现有 BigInt 十进制定点规则。
- [ ] 服务端本地长期保存原始证据与交易归并版本，优先验证现有 Node 运行环境中的 SQLite 支持；退出登录、清除本单和重启不删除历史。
- [ ] 真实与模拟来源独立，记录身份可追溯；演示不读取真实凭据或冒充真实交易，未知字段和不完整数据明确表达。
- [ ] 同一来源记录重复写入不会重复形成交易或费用；写入失败不留下半笔交易，已有账本保持可读。
- [ ] 如需提取既有共享读取或十进制入口，先进行保持已有契约的最小兼容调整，原有开仓及核验行为继续通过验证。
- [ ] 原有登录、Origin、静态资源白名单和 CSP 边界保持有效；手机与桌面可查看金额、单位及详情，焦点和展开操作遵循现有前端规则。
- [ ] 使用临时账本验证写入、读取、重启保留、去重与失败原子性；从公开业务入口和生产构建浏览器验证导航、详情及来源标识，测试不写入用户账本。
