# USDT 永续开仓止损助手：手机网页与只读账户核验

## Problem Statement

作为在 Binance 交易 USDT 本位永续合约的个人用户，我希望养成开仓必带止损的习惯。当前从亏损预算、止损距离、杠杆到仓位数量和实际止损委托，需要反复计算与切换操作，容易遗漏手续费、滑点、强平缓冲、数量精度和订单限制，也难以确认实际成交后的仓位是否仍符合原计划。

我需要保留对必要输入及交易执行的控制，同时用一个手机上友好、流畅、易用的工具生成明确的开仓方案，并在成交后依据 Binance 数据核验。工具必须区分计划止损亏损与实际亏损，不能用“止损已挂”承诺损失封顶。

## Solution

开发供个人、单 Binance 账户使用的手机网页版，兼容电脑，先完成本地测试再决定部署。核心流程为：填写亏损预算与止损条件，生成可逐项复制的开仓卡，到 Binance 手动带止损开仓，返回工具刷新并完成止损核验。

一期支持 USDT 本位永续、逐仓、单向持仓、做多与做空、市价与限价入场，面向目标币种从空仓开始的一次新开仓。用户自行输入止损价格或距离，或选择自己保存的止损模板；单层和双层止损均支持。双层按全部仓位在最终止损退出的情形确定仓位，而非利用加权距离扩大仓位。

后端使用专用只读凭据获取账户、行情、规则、持仓和挂单数据，减少手填并核验实际执行情况。所有下单、撤单与账户交易设置仍由用户在 Binance 完成。数据或核验条件不满足时，保留方案并明确指出问题，不生成新的可执行建议，也不自动放宽风险限制。

3. 作为个人交易者，我希望登录后才能访问工具及账户信息，以便我的交易数据不被未授权访问。

## Implementation Decisions

1. **执行边界已确定。** 产品生成开仓方案并进行只读止损核验，用户负责全部实际交易操作。沿用 ADR 0003“只读接入 Binance，由用户执行交易”，其已取代 ADR 0001 的不接账户限制；不恢复过时的纯手填账户方案。
2. **双层预算语义已确定。** 沿用 ADR 0002“按最终止损距离确定仓位”。单双层均按全部仓位在最终止损退出的计划损失控制数量；双层近端退出的潜在好处不用于增加初始仓位。
3. **责任集中。** 手机交互与后端业务入口组成最小完整产品；方案生成与成交后核验共享同一套风险、精度和规则判断。Binance 数据读取集中在外部边界，密钥与签名只在后端处理。当前没有可复用的应用模块，不预先规定内部文件布局或为每条规则建立独立服务。
4. **业务输入与输出。** 方案生成接收用户交易意图、个人风险偏好及当前账户、行情和合约规则；返回规范化的开仓参数、各层止损、成本假设、资金与风险检查结果、数据时间以及不可执行原因。核验接收固定的原方案与实际账户数据，返回偏差、覆盖情况、查询时点、修正建议和明确状态。
5. **支持范围。** 一期仅支持已验证的普通 USDT 单资产、逐仓、单向持仓场景，目标币种从空仓开始；支持多空、市价和限价。旧仓位或会干扰本次计划的旧委托需要用户先处理，工具不改变账户设置。
6. **账户数据口径。** USDT 账户权益由钱包余额与未实现盈亏构成，用作比例预算基数；资金充足性使用可用余额，不用权益代替，也不重复扣除已占用保证金。读取账户适用费率和杠杆档位，不以公开通用值假装账户实际值。
7. **预算固定。** 用户可填写 USDT 金额或权益比例；生成方案时换算并固定本单 USDT 预算。后续成交、权益或费用变化不自动改变该预算。首次不采用原问答的本金、预算或止损距离示例作为用户默认值。
8. **止损输入与模板。** 止损可输入价格或相对入场价的百分比。双层初始比例为 70/30，允许修改且两层均须有正数量。模板只复用百分比、层数和分配比例；固定止损价只属于当次交易。
9. **委托规则。** 所有初始止损均为止损市价、标记价格触发、关闭价格保护。输出绝对触发价及明确数量单位，不让使用者将止损距离误填成杠杆收益率或以最新价为基准的偏移百分比。
10. **入场与成本估值。** 市价做多参考卖一价、做空参考买一价，限价以用户委托价为基准。用户滑点预留分别作用于每次市价成交的不利方向；限价入场不模拟突破其限价的成交，但退出仍预留市价滑点。计划阶段开平仓费用按账户 taker 费率预留，不能自动假设普通限价入场为 maker；未知折扣不得降低预算成本。
11. **风险反推。** 先从预算扣除非负资金费预留，再按不利入场与最终止损执行估值计算每单位价格损失，加上入场及退出手续费，以剩余预算确定风险允许数量。资金费未预留时明确标注。费用、滑点和资金费均是可见假设，实际亏损可能偏离计算。
12. **合法数量与资金约束。** 最终数量同时满足风险预算、账户可用资金、可选本单资金上限、所选杠杆允许的名义价值和合约订单规则。资金需求包含初始保证金、适用开仓浮亏及开仓费用预留，按当前官方订单类型和方向规则估算。资金不足时缩量，不提高杠杆或缩短止损以增加仓位。
13. **价格与数量取整。** 使用可靠的十进制运算与实际交易步长，不能由显示精度推断规则。止损需取整时，多头向下、空头向上，明确展示变化并重算仓位；不符合步长的限价输入要求用户修正。数量向下取整并再次核算，不通过向上取整满足最小开仓要求。
14. **分层取整与退出例外。** 近端数量按适用步长向下取整，剩余归最终止损并展示实际比例。双层价格重合、近端数量为零或违反适用退出规则时拒绝当前双层方案。入场和退出分开验证，只减仓的最小名义价值例外不等于全部数量规则豁免；整仓平仓按其语义核验，不能强行套用开仓数量门槛。
15. **输入与即时触发检查。** 价格、预算、成本、比例和止损方向必须合法，预算必须覆盖预留成本。双层止损沿不利方向依次位于入场价之外；当前标记价已满足任一预设止损触发条件时，要求刷新或修正方案。
16. **杠杆与强平缓冲。** 用户选择杠杆，工具显示其保证金影响，不将固定仓位的价格风险再次乘以杠杆。最低强平缓冲是首次必填且可保存的正数偏好，以入场价百分比表达；多头比较最终止损价高于强平价的间距，空头比较强平价高于最终止损价的间距，不能取绝对值掩盖先强平的错误顺序。
17. **强平数据的阶段区别。** 成交前使用官方逐仓公式、账户档位及明确的保证金和成交假设估算，跨档时重算。成交后使用 Binance 返回的当前强平价和实际均价核验。缺少数据、未设缓冲或缓冲不足都不能通过，不用杠杆倒数替代完整检查。
18. **手机主流程。** 登录并完成低频设置后，在单页选择本单输入并即时预览；生成正式建议时刷新相关数据。主结果卡突出开仓数量、各层触发价及退出方式，支持逐项复制；名义价值、风险、资金需求、缓冲、假设和数据时间也须可查看。切换到 Binance 再返回时保留本单并重新查询。
19. **手动订单执行。** 用户开仓时附带最终止损，双层先确保整仓有最终止损保护再补近端部分止损。目标界面的实际设置方式和订单并存行为必须验证，不能仅凭 API 字段推断完整手机操作已经成立。
20. **止损核验。** 同时读取实际持仓、普通挂单及条件挂单，检查模式、方向、杠杆、有效状态、平仓语义、触发价格及依据、价格保护和数量覆盖。双层区分近端部分退出与远端剩余保护，不重复累计覆盖，也不把取消、失效或已执行的止损当成仍待触发。
21. **成交与余单处理。** 限价部分成交后先由用户撤销未成交入场余单，再核验实际仓位；不能假设止损会自动撤余单。近端已退出时，依据实际剩余仓位和可归属本单的成交、损益及成本重新核验；无法可靠关联则明确返回无法完整核验。
22. **异常与修正。** 成交后沿用原预算与原绝对止损价，展示超预算差额、覆盖缺口及可支持的修正建议；不得通过扩大预算或向更远处移动止损使检查通过。数据不足以产生可靠修正数量时，明确说明缺项。操作由用户完成，刷新复核后才可完成流程。
23. **状态与时效。** 区分草稿、待成交、待核验、需处理、已核验和已结束。已核验须带查询时间；空仓不意味着止损通过，页面关闭也不意味着持续监测。API 失败、权限缺失或快照不完整时保留输入及旧方案但撤销当前通过状态，暂停新建议；恢复后重查，不能静默改用手填或模拟值。
24. **凭据与访问保护。** 使用专用只读凭据，实际验证读取权限，失败时不扩大为交易权限。通过后端环境变量或既有密钥机制配置；浏览器、日志和源代码不接收密钥或完整签名请求。页面与账户接口均受访问保护，后端只能访问任务所需的读取接口，不能成为任意代签请求的代理。
25. **存储与交付。** 一期单人、单账户，无多用户注册；普通设置及模板在当前浏览器保存，保持当次计划可在切换 App 后继续，不做云同步。先在本地完成前后端及移动端验收；服务器、域名、部署平台、具体技术栈和测试工具尚未选定，不在本规格中假装已有决定。

## Testing Decisions

- **现有基础。** 当前项目只有问答、领域术语及规格/ADR 文档，没有应用代码、测试框架、已有测试入口或可复用测试先例。此前运行的文档链接与手算示例检查仅验证文档，不等于应用测试通过。
- **主要测试边界提案。** 统一从“生成开仓方案／核验实际持仓”的业务公开入口测试，真实执行输入校验、计算、规则处理和结果判断；仅在 Binance 外部读取边界提供可复现响应。优先一个主要业务边界，不逐个内部函数建立测试体系，也不为测试增加独立服务。此边界已按 to-spec 发起用户确认，当前尚未收到答复。
- **好的测试。** 断言使用者可观察的结果：数量、止损参数、成本与缓冲、能否生成建议、具体阻断原因、覆盖状态及时间信息。预期来自独立手算和明确业务场景，不在测试里复制实现算法，不依赖内部函数调用顺序、私有类型或内部文件布局。
- **受测责任。** 核心覆盖方案生成与止损核验的完整组合；只读集成的响应解析和异常也从相同入口验证。补充少量完整浏览器场景覆盖手机输入、复制、切换返回与恢复，及账户访问和只读请求边界，避免重复覆盖全部计算组合。
- **数据与真实联调。** 主要测试使用明确标识的模拟或脱敏数据，不依赖真实市场和账户资产。真实账户只做已授权的读取连通性与字段核对；不发出真实订单验证测试。外部双层操作流程以官方资料、界面检查及适当模拟环境补验，结果独立记录。

| 场景 | 对外可观察的验收标准 |
| --- | --- |
| 基准手算：预算 20 USDT、最终止损距离 1.6%、费用和滑点为零 | 理论名义仓位为 1250 USDT；双层 70/30 不因此扩大仓位，之后才应用虚拟合约规则。这些数值不进入产品默认设置。 |
| 同一仓位与止损只改变杠杆 | 价格损失不再次乘以杠杆；预计资金与强平结果可随杠杆变化。 |
| 多空、市价/限价、非零费用与滑点 | 不利成交方向正确，计划成本完整，最终数量取整后的计划损失不超过固定预算。 |
| 权益与可用余额不同、其他币种已有占款 | 比例预算使用权益，资金检查使用可用余额，不混用也不重复扣减占款。 |
| 委托估值相对标记价出现开仓浮亏 | 资金检查体现额外需求，不能因简单保证金足够而错误通过。 |
| 本单资金上限限制仓位 | 数量缩小，原止损和所选杠杆保留，并显示实际风险与资金占用。 |
| 价格/数量不在步长上或规则发生变化 | 结果符合新规则，明确展示修正或拒绝原因；不靠显示小数位判断合法性。 |
| 双层价格重合、近端量为零或最小开仓要求无法满足 | 拒绝当前方案，不静默改层数、增仓或放宽预算。 |
| 只减仓退出低于开仓最小名义价值 | 按退出适用规则判断，不误套开仓门槛；仍检查适用数量限制。 |
| 当前标记价已满足预设止损条件 | 不能生成看似有效的新方案，明确要求刷新或修正。 |
| 强平先于止损、缓冲不足、阈值或强平值缺失 | 均不能通过；多空方向正确，不通过绝对值掩盖错误。 |
| 止损方向、数量、触发价、触发依据、保护设置或平仓语义不匹配 | 返回具体不匹配项，保持需处理状态。 |
| 整仓与部分止损重叠、近端止损已执行 | 不重复累计覆盖，按实际剩余仓位判断最终止损，失效订单不算有效保护。 |
| 限价部分成交且余单仍在 | 不能完成核验；人工撤余单后按实际持仓重新判断。 |
| 实际成交偏差导致超预算，或已发生部分平仓 | 不改变原预算/止损来掩盖偏差；计入可归属本单的成本和损益；关联不清时拒绝伪精确核验。 |
| API 超时、权限不足、部分查询失败或数据明显不一致 | 旧输入及方案保留且标明时间；当前通过状态失效；不输出新可执行建议，恢复后可继续当前流程。 |
| 没有实际仓位或方案参数被修改 | 空仓不会显示止损核验通过，修改后必须重新检查。 |
| 模拟模式与真实数据切换 | 来源始终明确，模拟结果不能被当成真实交易建议或账户核验。 |
| 手机窄屏、键盘展开、错误输入及切换 App 返回 | 无横向滚动，单位和错误清楚，复制/刷新可触达，关键操作不被遮挡，本单保留且账户数据重新查询。 |
| 未登录访问或尝试利用后端发交易请求 | 账户访问被拒绝，后端不能下单、撤单或泄露密钥及签名请求。 |

## Out of Scope

- 自动根据行情、技术分析或交易周期推荐止损距离；该模块二期再讨论，尚未承诺实现。
- 自动下单、撤单、修改杠杆或保证金，及提现、划转等账户写操作。
- COIN-M、非 USDT 保证金、全仓、双向持仓、组合保证金及多资产保证金场景。
- 给已有仓位加仓、跨币种组合风险管理或多个 Binance 账户。
- 条件触发开仓、止盈策略、移动止损、盈利后的持续持仓管理。
- 按双层加权止损距离扩大初始仓位，或通过自动放宽预算/止损使失败检查通过。
- 断线时静默退回手填账户数据，或使用未核验缓存继续生成可执行建议。
- 多用户注册、模板云同步、完整交易历史、后台持续监控与推送通知。
- 把实际亏损保证封顶、把止损触发价保证为成交价，或保证交易所最终接受订单。
- 本地验收前选择服务器、购买域名或执行公网部署。
