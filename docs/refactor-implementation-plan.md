## 1. 交付范围与执行边界

产品与架构依据是[目标架构](architecture-nextjs-vercel-neon.md)、[ADR 0006](adr/0006-multi-user-product-migration.md)、[ADR 0007](adr/0007-account-binding-and-credentials.md) 和 [ADR 0008](adr/0008-persistent-business-service.md)。本计划维护实施顺序和完成条件，不重复维护业务规格。

- 交付公开官网、邮箱注册/验证、用户后台，以及现有开仓与核验、资产快照、交易记录、笔记、统计、行情、AI 和备份恢复。
- 每用户同时一个活跃 Binance 绑定；解绑后原账户只读归档，注销在线清理后才释放 UID。活跃绑定完整保留现有功能；Key 临时失效不等同解绑。
- Binance 和模型 Key 长期加密托管；用户承担自己的模型调用费，调用次数不限，通过排队控制并发。用户业务备份无凭据，平台受控灾备可含密文，主密钥单独保管。
- 保留固定预算/绝对止损、BigInt 精度、只读白名单、手动交易、北京时间及手机交互。旧数据迁移不伪造缺失证据，不将普通备份方案升级为可信当前本单。
- 一个代码库、一个 package、Next 与常驻 Node 两个运行入口。Next 部署 Vercel，数据目标 Neon；常驻主机、地区、预算在上线前确定。
- 首版不接 Sentry，不引入平台计费、独立队列产品或对象存储。现有 Vue 页面逐模块替换，整体视觉和交互不随框架迁移重做。

确认本计划后可实施阶段 1–5：代码、依赖调整、本地构建、合成数据测试、模拟与迁移工具演练。阶段 6 的采购、外部真实调用、真实数据写入/迁移和生产部署另行确认；本计划不授权真实交易。

## 2. 运行分工

| 部分               | 职责与限制                                                                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| Next.js            | 公开官网、React 页面、Better Auth、用户资料/设置、小请求受保护入口；不直接写交易账本或自行请求 Binance，不持有用户 Key 的解密主密钥 |
| 常驻 Node 业务服务 | 绑定与凭据管理、账户读取、计算/核验、账本、归档、AI 排队、报告/证据及文件传输；始终校验用户与账户归属                               |
| Neon PostgreSQL    | 认证、绑定、十二类账本数据、凭据密文、任务及必要并发状态；认证和交易模块各自拥有写入职责                                            |
| 独立恢复控制记录   | 保存必要用户/归属实例/凭据版本的删除与撤销决定，不随业务库恢复点回退，不包含交易内容或 Key；具体部署机制在恢复演练中验证            |
| 秘密管理机制       | 主密钥与数据库分离、按服务授予访问、支持版本及轮换；本地仅使用合成测试密钥                                                          |

Better Auth 保持唯一身份源。Next 签发短期受限委托凭据，业务服务每次检查当前原会话、用户状态、授权代次和资源归属；浏览器凭据仅放内存及请求头。登出使页面访问失效，已接受后台任务按明确任务生命周期继续。

## 3. 最终审查中补齐的工程约束

| 已识别问题                                            | 实施要求与验收                                                                                                                                         |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| AI 任务、统计和详情也可能产生大 JSON                  | 小请求保持同源；大响应与 64 MiB 恢复走受保护 Node 直连。任务摘要、历史分页、证据分块均可回溯完整数据，不截断分析范围；以超过 4.5 MB 的合成响应验收     |
| 单账户协调器不能直接共享给所有用户                    | 出口 IP 额度/冷却共享，签名、私有缓存、权限错误按用户/绑定/凭据版本隔离；两用户同时请求相同 URL 不串数据                                               |
| 单进程任务的 Map/AbortController 不足以应对重启与交接 | 数据库原子领取、租约、执行版本和检查点；同账户归档串行、AI 公平排队；中断后人工继续，结果未知的收费请求不自动重放                                      |
| v1 备份只有 UID，没有产品归属                         | 新 v2 封装增加不可复用归属实例及服务端证明；旧 v1 仅经受控迁移转换。已注销归属的包不能恢复到同 UID 的新用户；普通导入不获得当前本单信任                |
| 恢复旧数据库可能抹掉后来发生的注销/撤销               | 相关决定在恢复点之外有可靠记录，确认操作成功前先落地；恢复隔离重放并更新恢复代次。记录缺失时不开放用户访问或外部调用，按原归属实例处理而非仅按 UID     |
| 新写入后旧 SQLite 已落后                              | 新系统开放写入前可撤销切换；首次新写入后只回滚兼容当前 Neon 的应用，或维护并保全新数据。旧库仅只读对账，不恢复可写；平台迁移副本也受最长 30 天清理约束 |

这些是已确认产品边界的实现要求，不新增产品范围。具体库用法、安全补丁及部署参数在实施时查对应官方文档并验证，不凭架构稿推定兼容。

## 4. 分阶段实施

### 阶段 1：基线、工程与身份入口

**工作：**先记录原版本 `pnpm check` 结果，分清已有失败与迁移回归；建立 Next/React 与常驻 Node 的独立运行入口，统一 Node 24 目标与配置校验，保留 pnpm 和现有测试。接入 Better Auth、邮箱密码注册/验证/恢复及资料安全页，开发邮件使用 fake adapter，完成 Next → 业务服务的受保护垂直请求。

**主要文件：**[package.json](../package.json)、现有 TS/ESLint/构建配置、[src/main.ts](../src/main.ts)、[src/server.ts](../src/server.ts)，新增 Next 路由和认证模块；依赖选择与理由纳入改动说明，实际新增依赖时才更新锁文件。

**完成条件：**两种入口都能在本地启动与构建；两个合成用户可独立注册、验证、登录及登出；未验证、停用、撤销会话及伪造委托凭据不能访问受保护业务。Next 的生产构建不需要解密主密钥或迁移 DDL 凭据。

### 阶段 2：账户归属、密钥与 PostgreSQL 账本

**工作：**建立活跃/归档绑定、UID 占位、凭据版本和注销状态；密文采用标准认证加密，主密钥独立提供。迁移十二类账本记录及调用方的同步/异步边界，保留金额字符串、BigInt、笔记版本与预览恢复事务。建立 v2 备份归属封装、受控 v1 转换和独立删除/撤销记录。

**主要文件：**[src/review-ledger.ts](../src/review-ledger.ts)、[src/review-backup.ts](../src/review-backup.ts)、[src/review-notes.ts](../src/review-notes.ts)、[src/review-export.ts](../src/review-export.ts)、[src/server.ts](../src/server.ts)，新增 Prisma schema/migrations、绑定和凭据模块；共享 [public/draft.js](../public/draft.js) 算法保留。

**完成条件：**真实本地 PostgreSQL 集成测试通过；同 UID 并发绑定仅一个成功，同用户不能同时激活两个账户；同 UID 换 Key 保留历史，换 UID 不改挂；归档只读，Key 临时失效仍能维护本地记录；注销清理含旧版本和冻结快照，释放后新用户不继承旧资料；备份不可跨归属恢复或泄露凭据。并发笔记/恢复、回滚及金额对账有可重复测试。

### 阶段 3：业务执行、任务与数据通道

**工作：**业务服务承接开仓/核验、Binance 调度、历史归档和自备 Key 的 AI 排队。分开共享出口预算与私有请求状态，持久化任务执行权、取消和检查点。实现受限直连、摘要/分页/证据获取及 64 MiB 恢复，恢复和注销与任务写入互斥。

**主要文件：**[src/account.ts](../src/account.ts)、[src/account-refresh.ts](../src/account-refresh.ts)、[src/market.ts](../src/market.ts)、[src/verification.ts](../src/verification.ts)、[src/history-sync.ts](../src/history-sync.ts)、[src/account-archive.ts](../src/account-archive.ts)、[src/order-download.ts](../src/order-download.ts)、[src/order-file.ts](../src/order-file.ts)、[src/trade-analysis.ts](../src/trade-analysis.ts)、[src/analysis-model.ts](../src/analysis-model.ts) 和 HTTP 入口。

**完成条件：**替换 transport 的模拟流程通过；并发用户不串签名/缓存/错误；冷却、前台优先、重启和双实例交接正确；取消、密钥撤销、换 Key、注销后无新的未授权调用或迟到写入；已发出请求保留费用未知语义。完整大响应与恢复可传输，过期/重放/跨用户文件授权被拒绝，不经 Next 重新包装超限载荷。

### 阶段 4：React 页面等价迁移与官网

**工作：**按开仓 → 账户资产 → 交易复盘的顺序迁移组件和页面状态，复用领域逻辑、原样式及浏览器断言；保留 `/entry`、`/account`、`/review`，受保护首页进入 `/dashboard`，公开 `/` 实现官网。增加绑定、归档账户浏览、AI Key、资料、安全及注销流程；本地状态和缓存按产品用户/账户隔离。

**主要文件：**[frontend/](../frontend/)、[public/style.css](../public/style.css)、[public/select.js](../public/select.js)、[public/login.html](../public/login.html)、[test/browser/](../test/browser/)，新增 React 页面。迁移完成后移除无人使用的 Vue/Vite 依赖与入口；同步[前端规则](../public/AGENTS.md)，保留其中的业务、语义及手机验收要求。

**完成条件：**活跃账户原功能全部可用；3 秒/30 秒刷新、复盘手动读取、北京时间、恢复重查、未保存提示、请求取消及迟到响应行为一致。Chromium/WebKit 覆盖 320px、390px、1280px，验证焦点、键盘、复制、隐藏/禁用及切换 App；两个用户及跨标签切换不显示旧隐私。官网原始 HTML 与 noindex 边界、CSP 和生产样式通过，未增加分析追踪或 Sentry。

### 阶段 5：迁移演练、恢复与本地完整交付

**工作：**用合成旧 SQLite 和恢复凭证演练十二类数据迁移、原拥有者认领、旧 origin 的浏览器状态迁移和当前本单验签。演练取消切换、开始新写入后的应用回滚、隔离恢复、删除/撤销重放及 30 天清理。统一 `pnpm check` 覆盖新工程，更新 README、规格、使用说明、开发文档与状态证据。

**主要文件：**新增一次迁移/对账工具及 runbook，现有 Node/浏览器测试、[docs/development.md](development.md)、[docs/status.md](status.md)、[docs/usage.md](usage.md)、[README.md](../README.md)。普通生产接口不保留任意旧库认领或伪造当前方案入口。

**完成条件：**同一基线完整检查通过；旧/新记录、金额、统计、原方案和笔记版本可对账，旧本单固定预算/止损不变。没有可信 UID/签名的本单不被自动认领，此账户切换需先在旧工具完成本单。恢复缺少独立控制记录时保持关闭，注销后的同 UID 新绑定不被旧删除记录误伤；所有测试均未读取真实凭据或修改真实账本。

### 阶段 6：外部验证与试运行切换

**前置选择：**主要用户地区、月预算、常驻主机与数据库区域、域名和邮件发信身份、主密钥保管及独立恢复控制记录的具体设施。根据实际套餐和连通性选择，不默认新加坡或每月 100 美元。

**工作：**经单独授权建立隔离环境并验证 Neon、真实 Binance 只读权限/UID/出口限制和模型 Key；验证生产 CSP、委托访问与大数据通道，实测恢复、保留清理及费用。实体手机与 Binance App 验收按现行未完成清单分别记录。先停旧任务和写入、保全原库、导入对账，再切换并开放新系统写入；不做长期双写。

**完成条件：**外部链路、实体设备、恢复和成本证据齐全；试运行资源、真实数据迁移与部署获得明确确认；切换失败可按所处写入阶段执行正确回退。公开文案、隐私/条款和数据去向与真实实现一致，不把未通过的链路描述为可用。
