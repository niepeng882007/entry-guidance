# 使用说明

启动步骤见 [README](../README.md)，实现与验收边界见[项目现状](status.md)。

## 页面与登录

登录后首页提供三个入口：开仓卡 `/entry`、交易记录 `/review`、我的账户 `/account`。后两页标题分别为“交易记录分析”和“账户快照”。首页不查询账户或交易历史。桌面使用侧栏，手机通过页首“菜单”切换页面。

会话有效期 8 小时，退出、服务重启或到期后需要重新登录。连续 10 次失败登录会限制 15 分钟。真实模式读取失败不会切换成模拟数据。

## 开仓卡

1. 选择合约、方向、市价或普通 GTC 限价，填写固定金额或权益比例预算、杠杆、单层或双层止损。首次需要填写滑点和最低强平缓冲；资金费预留及本单资金上限可选。示例参数不是默认建议。
2. 查看草稿后点击“刷新并生成开仓卡”。正式卡经过资金、交易步长、账户档位和强平缓冲检查，固定本单 USDT 预算、数量和绝对止损。
3. 按卡片逐项复制参数，在 Binance 手动执行。卡片生成不表示交易所已经设置止损。双层方案的 Binance iOS 组合设置流程仍有[未完成验收](status.md#未完成验收与限制)。
4. 返回工具后刷新核验。限价部分成交时先在 Binance 撤销入场余单，再按实际持仓核验；显示的通过结果仅代表该查询时点。
5. 修改输入、查询失败、离线或离开页面会撤销当前通过状态。恢复原输入并重新查询后才可继续，原预算与止损不会自动放宽。

开仓页摘要正常每 3 秒读取；选定币种后的完整查询在上一轮结束后等待 10 秒，修改输入停止 500 毫秒后重查。正式生成和核验仍使用完整查询，账户观察缓存不能使旧卡恢复有效。

核验只支持能唯一关联本单的开仓与退出证据：一张开仓订单可包含多次成交；历史区间须少于 7 天，各类记录最多 1000 条，满页即拒绝完整核验。单层手工部分平仓、多张开仓单和撤单重挂不属于完整核验范围；双层部分退出须关联原近端止损。具体口径见[计算与核验实现](entry-implementation.md)。

### 模板与本单恢复

止损模板保存百分比、层数和原分配比例，存于当前浏览器。固定价格按明确的入场参考价换算后保存；选择模板不会修改输入，点击应用才生效，并撤销旧通过状态。模板不保存币种、预算或资金设置，也不自动生成正式卡。

本次输入和签名原方案保存在当前浏览器。关闭、重登和服务重启后可恢复；服务端确认原方案后仍须重新查询。修改应用密码、账户配置或真实/模拟模式可能使旧恢复凭证失效。“开始新一单 / 清除本单记录”不改变交易所仓位，也不删除服务端复盘账本。存储损坏或写入失败会提示，不能据此认为已保存。

## 账户快照

`/account` 当前仅展示资产：账户权益、可用余额、未实现盈亏，以及钱包余额、保证金占用、可转出额和查询信息。资金明细每次进入默认展开，刷新保留当前展开状态。

正常前台每轮完成后等待 30 秒刷新；手动刷新、返回和联网恢复主动读取，但遵守后端冷却。隐藏、离线或离开时暂停。旧金额保留原成功时间并标为“数据待更新”，首次没有数据时显示占位。错误原因在主栏简述，原始错误放入默认收起的“错误详情”。

此页已移除持仓和活跃委托列表，也不为这些模块读取辅助行情。账户快照不等于止损核验；开仓与核验所需的后端持仓、委托读取仍保留。字段与状态要求见[账户快照规格](account-snapshot-spec.md)。

## 交易记录与完整交易复盘

默认 `/review` 一行一张订单，按北京时间订单日期和交易对筛选，每页 20 张。保留取消、过期及部分成交订单；展开查看编号、委托参数、费用和关联周期。订单已实现盈亏汇总逐笔成交，不含手续费和资金费；成交未补齐显示待确认。

切换“完整交易复盘”进入 `/review?view=cycles`。一笔记录对应同一合约、同一方向从空仓到再次空仓的周期；加减仓归入该周期，反手可以关联两个周期。统计、笔记、行情、模型分析与 CSV 都采用周期口径。持仓中和不完整记录仍可查看，缺失成本不按零计算。

编辑日期或交易对后点击“查询”才提交；“重置”清空条件并重新查询。完整交易按北京时间开仓日期筛选，统计、批量分析和 CSV 使用已提交的全部匹配范围，分页仅影响显示。服务端还支持其他组合条件，当前页面只展示日期与交易对。

### 手动更新与本地读取

- “手动更新至当前”：确认只读权限与稳定 UID，首次默认最近 3 个月，下载订单后用普通接口补成交、费用及周期证据。
- “补查所选日期”：按北京时间日期生成订单文件，单次最多一年。下载窗口不保证历史全部可取得；旧盈亏与费用仍可能缺失。
- “读取本地记录”或完整交易视图的“重新读取”：更新已归档列表与进度，不生成外部下载任务。订单视图在手动更新启动后先读取一次，之后由用户重新读取查看进度。
- “归档管理”：查看进度、缺口、单合约补查与原始证据。失败或中断后主动继续；已有下载 ID 会复用，生成结果不明且没有 ID 时不会自动再生成。

服务启动、等待五分钟、进入复盘、筛选、翻页、切换周期及恢复联网均不触发复盘 Binance 取数。列表在同步期间也不轮询；单笔和批量模型任务有独立进度轮询。一次已启动的后台任务可在关闭页面后继续，服务重启后需要主动继续。

首次确认 UID 后，同一后端配置重启可读取旧账本；旧账本升级或更换密钥后须手动更新重新确认身份。不同账户及真实/模拟来源隔离，同一 UID 更换密钥不构成新账户。

### 详情、笔记、统计与行情

详情显示盈亏分项、成交证据、原方案对照及个人记录。只有核验与成交证据唯一匹配时才关联原方案；缺少原计划不判断违反计划，未记录的历史杠杆、保证金模式与止损变化保持未知。

笔记可记录入场理由、退出理由、执行问题、改进事项及自由文本，并应用自己确认的标签。结构化字段最多 2000 字，自由笔记最多 10000 字；最多 100 个标签，每个名称 1–40 字，一笔最多应用 20 个。标签可改名或停用，历史关联保留。保存不调用模型。

跨设备旧版本保存会被拒绝，输入保留；重新读取已保存版本后再编辑。页内列表/详情切换保留未保存草稿，整页离开会提示。归并依据改变时保留旧笔记并标为归属待确认，当前不支持手动重新绑定。

“表现统计”使用全部筛选周期，分别列出各指标有效与排除样本。累计净盈亏是所选交易结果，不是账户权益曲线。

行情默认读取本地已归档的 15m 数据，可切换 1m / 5m / 15m / 1h / 4h；缺失时须点击“继续读取 / 重试行情”才连接 Binance。合约价、标记价、交易事件与止损证据分别表达；图表抽稀不改变归档原值或分析输入。数据缺口和时间仍可见。

### 模型分析

在交易详情主动发起单笔分析，或在完整交易列表发起当前筛选范围分析。批量上限为 100 笔，含因缺项而排除表现结论的记录；超过时缩小范围，不抽样，不设每日次数上限。

发起时选择是否发送已保存笔记，未保存草稿不会发送。任务冻结所选交易、费用、方案、标签、允许的笔记及全部已归档周期行情；不会为分析自动补行情。超过模型容量时分段后综合，任一段未完成则整体未完成。

已有同依据报告可复用。“继续”沿用原证据和完成分段；“重试 / 重新生成”冻结当前证据并创建新任务，旧报告保留。取消、中断或未知用量可能仍产生上游费用，不自动重复收费请求。模型风格建议须由用户确认后保存为个人标签。

后端配置参照 [`.env.example`](../.env.example)。当前实现只接受 `LLM_PROVIDER=deepseek`、`LLM_MODEL=deepseek-v4-pro`、`LLM_EFFORT=high` 和服务端 `LLM_API_KEY`；这是代码支持条件，不表示本机已配置或真实模型已验收。

### CSV 与备份恢复

进入“完整交易复盘”，展开“导出与备份恢复”。

CSV 导出全部已提交筛选范围的交易、原始十进制金额、状态、缺失项、标签与已保存笔记；它不是可恢复备份。

完整备份为同账户 JSON v1，包含原始证据、交易、方案与核验、行情、笔记、标签、报告、未完成分段和同步状态，不包含凭据、登录会话或本单恢复签名。恢复最大请求 64 MiB，先校验账户、模式与版本并预览；有拒绝项或预览后账本变化须重新处理。

恢复默认补缺与去重，原始证据和报告冲突保留当前值。仅同身份笔记/标签冲突可逐条选择覆盖，双方版本均保留。写入在同一事务内完成；同步区间标为待重读，未完成分析保持中断，不自动调用模型或恢复当前本单。

## 数据保存位置

正式启动按模式将账本保存在 `.local/review/real.sqlite` 或 `.local/review/demo.sqlite`，默认模式为 `real`。可用 `REVIEW_DATA_DIR` 指定目录，相对路径按启动目录解析；切换目录不会搬迁旧账本。

浏览器保存偏好、止损模板和当前本单；复盘事实、笔记及报告保存在服务端账本。清除浏览器数据不会删除服务端复盘，服务端备份也不恢复浏览器偏好。数据库不作为静态资源发布。

## 手机连接本地电脑

手机与电脑处于同一可信局域网，手机使用构建后的 HTTPS 服务。电脑本机开发热更新仅支持本机 HTTP，详见[开发与验证](development.md)。

已有可信证书时直接设置下面三个变量。也可生成本地测试证书，将示例 IP 换为电脑局域网 IP：

```sh
LAN_IP=192.168.1.100
mkdir -p .local
openssl req -x509 -newkey rsa:2048 -nodes -days 30 \
  -keyout .local/key.pem -out .local/cert.pem \
  -subj '/CN=Entry Guidance Local' \
  -addext "subjectAltName=IP:${LAN_IP},IP:127.0.0.1,DNS:localhost" \
  -addext 'basicConstraints=critical,CA:TRUE'
chmod 600 .local/key.pem
```

仅将 `cert.pem` 安装并信任于手机，私钥 `key.pem` 留在电脑。在本机 `.env` 合并设置：

```dotenv
APP_ORIGIN=https://192.168.1.100:3000
TLS_CERT_FILE=.local/cert.pem
TLS_KEY_FILE=.local/key.pem
```

重新构建并重启后，手机与电脑访问同一个 HTTPS 地址。服务仅绑定 `APP_ORIGIN` 指定地址。证书留在被 Git 忽略的 `.local/`；项目未配置公网部署。
