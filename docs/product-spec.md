# 开仓止损工具：产品决策

状态：产品决策已确认，完整规格待整体确认，尚未进入实现。后文计算与验收规则是对已确认决策的具体化。

## 使命与核心原则

- 帮助使用者养成开仓必带止损的习惯，减少从亏损预算、止损设置到仓位参数的计算和操作负担。
- 使用者决定必要输入；按亏损预算和止损条件反推仓位。
- 输出简洁、明确，符合 Binance 永续合约的实际订单场景。
- 计划止损亏损是明确假设下的估算，不承诺实际亏损封顶。

## 已确认只读账户接入（Q14 修订）

- 一期加入 Binance 只读 API，保留用户手动下单、撤单及其他交易操作的边界。
- 开仓前读取账户权益、可用保证金、费率和用户杠杆档位；拟开仓的强平价仍是按计划参数计算的估值。
- 成交后读取实际持仓与挂单，包括普通挂单和条件挂单，核验当前强平价及止损覆盖；结果对应明确查询时点，不承诺持续有效或未来成交。
- 使用专用只读凭据，不授予交易、提现或划转权限；读取权限需在实际接入时进行连通性验证。
- 密钥由后端环境变量或现有密钥机制配置，不放入聊天、源码、前端代码或浏览器持久化存储。
- 增加后端与网页访问保护；一期单人、单 Binance 账户使用，先本地测试，完成后再决定部署平台。API 凭据尚未配置，当前阶段未读取实际账户。

## 手机使用流程

1. **首次设置**：完成个人访问验证和后端只读凭据配置；设置每次市价成交的滑点预留、最低强平缓冲和可选资金费预留。费率从账户读取，展示数据来源及费用假设；不要求将密钥填写到手机表单。
2. **填写本单**：选择币种、做多/做空、入场方式、预算、杠杆、单层/双层止损。限价单才填写限价；止损可填价格或百分比，也可选模板。可选本单资金上限，低频设置折叠，常用选择记忆。
3. **查看方案**：修改输入即时计算草稿；生成正式建议前刷新账户、行情与合约规则。结果卡优先展示开仓数量、绝对止损触发价及各层退出方式，同时列出名义价值、预计资金需求、计划止损亏损、强平缓冲、假设和数据时间。
4. **手动执行**：按卡片到 Binance 设置逐仓、单向持仓、所选杠杆及开仓订单，并附带最终止损。双层方案先确保整仓有最终止损保护，再设置近端部分止损；具体界面步骤须通过下文列出的外部验收。
5. **返回核验**：切换 App 后返回保留本次方案，刷新账户、持仓及普通/条件挂单。限价只成交一部分时提示用户先撤余单，再按实际仓位复核。
6. **完成或处理**：预算、强平缓冲、实际止损覆盖和入场余单均符合要求后，显示“已核验 · 查询时间”。否则展示具体问题；处理后再次刷新。没有实际仓位时显示“待成交”或“已结束”，不能据此宣称止损核验通过。

卡片逐项复制的价格使用绝对价格，数量标注币种单位，避免与 Binance 界面的 ROI%、Offset% 或 USDT 金额混淆。默认流程不引入行情分析、长期持仓监控或交易历史系统。

## 计算规则

### 账户与预算

- 仅在已验证的普通 USDT 单资产、逐仓、单向持仓场景生成正式建议；目标币种必须空仓且没有会干扰本次计划的旧委托。其他账户模式或旧仓位需要先由用户处理，工具不改变账户设置。
- 账户权益使用 USDT 资产的权益口径；资金充足性使用 USDT 可用余额，不用账户权益代替可用余额，也不重复扣除已占用保证金。
- 固定金额直接作为本单预算；比例输入按本次读取的账户权益换算。生成方案时固定本单 USDT 预算，成交后不随权益变化自动抬高或调低它。

### 止损、滑点与仓位

下面是本工具的预算估算约定，不是对未来成交的保证。价格按同一报价币种计量，百分比参与运算时转换为小数。

| 符号 | 含义 |
| --- | --- |
| `E` | 入场参考价；市价做多参考卖一价、做空参考买一价，限价使用用户委托价 |
| `D` | 方向：多头 `+1`，空头 `-1` |
| `s` | 用户配置的每次市价成交滑点预留，`0 ≤ s < 1` |
| `S` | 按交易步长处理后的最终止损触发价 |
| `fe` / `fx` | 入场/退出手续费率；计划阶段按账户 taker 费率预留，不能把普通限价单自动当成 maker |
| `R` / `F` | 本单 USDT 亏损预算 / 非负资金费预留；`F` 未填则为零，并显示未预留资金费 |

```text
不利入场估值 Ew = E × (1 + D × s)   // 市价入场
不利入场估值 Ew = E                 // 限价入场
不利退出估值 X  = S × (1 - D × s)
每单位计划损失 u = D × (Ew - X) + Ew × fe + X × fx
风险允许数量 Qrisk = (R - F) / u
```

- 输入必须合法：价格和预算为正、`R > F`、`u > 0`、止损位于不利方向。双层多头要求 `S远 < S近 < E`，空头相反；各层数量比例均大于零且合计 100%。
- 生成新方案时还须核对当前标记价；任何预设止损已满足触发条件时，要求刷新或修改计划，不能仅因止损位于入场参考价的不利方向就判断有效。
- 单层、双层都按全部数量落到最终止损计算风险；双层近端成功退出后的预计损失可作辅助信息，不据此扩大仓位。
- 止损价格需要取整时，多头向下、空头向上，保持不缩短用户给定的止损空间；明确展示实际价格与距离，再重新计算仓位。限价入场价格不符合价格步长时提示修正，不静默改变委托价。
- 取同时满足风险预算、资金上限、账户允许杠杆/名义价值和适用交易规则的最大合法数量。数量向下取整后再次核算风险和资金需求，不通过向上取整满足最小开仓要求。
- 双层近端数量按适用数量步长向下取整，剩余量归入最终止损；展示实际比例。两层价格取整后重合、近端量为零或不满足适用退出规则时，不生成该双层方案，提示调整输入或主动选择单层。
- 价格、数量和金额计算不得依赖显示小数位推断步长；使用可验证的十进制计算方式，计算与显示精度分别处理。

### 开仓资金与交易规则

- 预计资金需求包括初始保证金、适用的开仓浮亏（Open Loss）及开仓手续费预留。初始保证金的估值价格须按当前官方订单类型/方向规则处理，不能把 `E × 数量 ÷ 杠杆` 当作完整下单成本。
- 资金上限取账户可用余额和用户本单资金上限的较小值；未填写本单上限时仅使用账户可用余额。资金不足只缩小仓位，保持止损与所选杠杆。
- 按当前合约规则校验价格、数量、名义价值、订单类型和账户档位；无法支持或缺失关键规则时不宣称可执行。普通数量限制与市价数量限制按适用订单分别处理。
- 开仓与退出分开校验：真正只减仓退出存在最小名义价值豁免，不能据开仓门槛拒绝合法止损；固定数量退出仍校验适用数量限制。整仓平仓按其订单语义检查，不强行构造提交数量。
- 以上是计划校验；行情、余额或交易所规则变化仍可能使实际下单被拒绝，结果不标成“保证下单成功”。

### 强平缓冲

```text
多头缓冲 = (最终止损价 - 强平价) / 入场价
空头缓冲 = (强平价 - 最终止损价) / 入场价
通过条件 = 缓冲 ≥ 用户设定的正数最低缓冲
```

- 使用有方向的差值，不能取绝对值掩盖“先强平、后止损”。未设置阈值、缺少有效强平价或缓冲不足时不能检查通过。
- 开仓前依官方逐仓公式、用户档位和明确的保证金/成交假设估算强平价；跨档时重新计算并展示估算性质。不能用 `1 ÷ 杠杆` 代替完整强平检查。
- 成交后使用 Binance 返回的当前强平价及实际均价重新检查。降低杠杆、增加逐仓保证金等修正由用户操作；不通过拉近止损让检查通过。

## 订单核验与异常处理

- 同时读取实际仓位、普通挂单和条件挂单；核对方向、逐仓/单向模式、实际杠杆、预算与计划关联。只看到一张止损单不等于覆盖正确。
- 止损须为有效的市价止损、标记价触发、关闭价格保护，并具有正确平仓方向及整仓/只减仓语义。固定数量、触发价、双层比例和当前覆盖需符合已生成方案及成交后的实际数量。
- 双层核验分别检查近端部分退出与远端剩余仓位保护；不能把重叠的整仓止损和部分止损数量简单相加。已成交、取消或失效的委托不能仍算作待触发保护；若近端已成交，按实际剩余仓位及成交记录判断。
- 当前币种仍有未成交入场余单时，不标记本次流程完成。工具指出待撤订单，由用户处理；不认为触发止损会自动撤销入场余单。
- 成交偏差后沿用原本单预算和原绝对止损价复核，不自动扩大预算或把止损往更远处平移。给出超额、覆盖缺口及基于最新数据的修正建议；无法可靠计算修正数量时说明缺少什么，不提供伪精确值。
- 已发生部分平仓或费用支出时，核验须计入可归属于本单的已实现损益和成本，再评估剩余敞口；无法可靠关联本次计划时显示“无法完整核验”，不以剩余仓位损失冒充整笔交易风险。
- API 失败、权限不足、关键数据缺失或快照明显不一致时，保留已有参数和查询时间、取消当前通过状态，暂停新开仓建议。旧止损计划仍可查看；恢复后重新查询，不能无提示切换成手填或模拟结果。
- 核验通过只对应显示的查询时点。用户修改方案或刷新发现账户/挂单变化后需重新核验；手机页面关闭期间不宣称持续监测。

## 本地实现与验收

- 先在本地完成前后端、响应式界面、个人访问保护和只读集成。配置凭据前可用明确标识的模拟数据测试计算与流程，模拟结果不能成为真实交易建议；真实账户联调只读，不以真实下单验证功能。
- 密钥只在后端使用；浏览器和日志不接收密钥或完整签名请求。Binance 请求限制到任务所需读取接口，不能成为可任意代签交易请求的代理。页面及账户数据接口均有访问保护。
- 移动端验收包括窄屏无横向滚动、数值键盘、明确单位、可触达的复制/刷新操作、内联错误、键盘不遮挡关键操作、切换 App 返回后保留本单且重新查询；同时检查桌面布局。
- 关键逻辑使用可运行的计算/契约检查覆盖下表；不以实际账户资产试验订单行为。

| 验收场景 | 必须满足的结果 |
| --- | --- |
| 纯数学示例：预算 20、最终止损距离 1.6%、成本及滑点均为零 | 理论名义仓位 1250；双层 70/30 与单层采用同一最终止损风险上限，随后才应用虚拟合约规则。该示例不作为默认参数。 |
| 同一名义仓位及止损，改变杠杆 | 价格风险不被再次乘以杠杆；保证金与强平检查相应变化。 |
| 多空、非零费用与滑点、数量取整 | 不利成交方向正确，取整后计划损失不超过预算，账户权益与可用余额不混用。 |
| 标记价与委托价存在不利偏离 | 资金检查计入开仓浮亏，不仅检查名义价值除以杠杆。 |
| 双层价格重合、近端量为零、入场低于最小门槛 | 明确拒绝当前方案；不擅自增仓、改变分层或放宽预算。 |
| 只减仓止损低于开仓最小名义价值 | 按退出适用规则处理，不因套用开仓门槛误拒绝；其他数量限制仍检查。 |
| 强平价先于止损、缓冲不足、强平数据缺失 | 均不能检查通过；多空使用有方向的距离。 |
| 止损数量不足、方向错误、触发依据错误、被取消或价格保护开启 | 明确显示实际不匹配项，不完成止损核验。 |
| 近端止损已执行或限价仅部分成交 | 按实际剩余仓位核验，追踪本单已实现成本；有入场余单时要求人工处理。 |
| API 超时、权限缺失、部分查询失败或切换 App 返回 | 不把旧数据当成新结果，不保留无效通过状态；恢复后可继续当前流程。 |
| 未登录访问账户接口或尝试代理交易请求 | 拒绝访问，凭据不出后端，不能通过工具下单或撤单。 |

## 实现时必须核实的外部条件

1. 当前账户的专用只读 Key 能读取所需账户、档位和普通/条件挂单接口；不为解决失败而扩大交易权限。
2. Binance 目标手机入口中，开仓附带最终止损、近端部分止损及远端整仓保护的实际设置与并存行为。确认前不把整套双层界面路径标为已验收；通过官方资料、界面检查及适当的模拟环境验证，不擅自使用真实账户下单。
3. 实现时核对当前合约过滤规则、逐仓强平公式和开仓成本规则；官方示例与实时规则不一致时查明差异，不硬编码示例交易门槛。

服务器、域名和公网部署在本地验收完成后另行决定。本轮不部署、不收取 API 凭据；整体规格确认后才开始实现。

## 已核验的平台约束

资料核验日期：2026-09-21。平台规则在实现时需再次核验。

- 止损市价的触发价不是保证成交价；实际亏损可能偏离预算。[Binance 止损订单说明](https://www.binance.com/en/support/faq/detail/360036351051)
- Binance 界面支持在限价、市价等开仓订单上附加 TP/SL；该界面能力不等于 API 的原子下单能力。限价部分成交需要单独考虑剩余入场委托和止损覆盖。[Binance TP/SL 说明](https://www.binance.com/en/support/faq/detail/e1ee1738141c49718550fa9061be4bf3)
- 订单参数需符合所选合约当前的价格与数量过滤规则，不能直接用显示精度代替价格或数量步长。[Binance 市场数据 API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)
- 用户实际杠杆档位、手续费率属于账户数据；通用公开规则不能证明某个账户的实际可用杠杆或有效费率。[Binance 账户 API](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/account)
- 逐仓强平价依赖入场价、仓位数量、逐仓钱包余额及维持保证金档位；仅有杠杆倍数不足以精确确定实际强平价。[Binance 强平价公式](https://www.binance.com/en/support/faq/detail/b3c689c1f50a44cabb3a84e663b81d93)
- 启用价格保护时，标记价与最新价偏差超过阈值可能阻止止损触发；本产品选择关闭该功能，属于执行优先级的取舍。[Binance 价格保护说明](https://www.binance.com/en/support/faq/detail/2b9dc811ce7340469357867122b975dc)
- 开仓附带 TP/SL 与持仓页的整仓止损不是同一概念；标为 `Close Position` 的整仓止损针对变化后的剩余仓位，固定数量止损仅针对指定数量。网页和 App 支持部分止损，但“先设远端整仓止损，再补近端部分止损，两者并存”的完整界面流程仍需验收，不能仅凭 API 语义当成已验证的界面操作。[Binance TP/SL 说明](https://www.binance.com/en/support/faq/detail/e1ee1738141c49718550fa9061be4bf3)、[分批止损说明](https://www.binance.com/en/support/faq/detail/717a9635f035490baffa564e2f19c7c1)
- 官方提醒止损子单可能在入场主单完全成交前完成，并未保证此时自动撤销入场余单。由此推导：手动执行流程必须单独处理未成交入场余单，不能假定止损后不会重新形成仓位。[Binance TP/SL 说明](https://www.binance.com/en/support/faq/detail/e1ee1738141c49718550fa9061be4bf3)
- API Key 本身不足以调用签名账户接口：常见 HMAC Key 还需要 Secret 生成签名，其他密钥类型使用相应私钥。读取权限与交易权限应区分，最小权限原则适用于账户核验工具；密钥可通过后端环境变量或现有密钥机制配置，不进入聊天、源代码或浏览器持久化存储。[Binance API 密钥说明](https://www.binance.com/en/academy/articles/what-are-api-keys-and-security-types)
- 账户、用户费率和杠杆档位，以及现有持仓、普通挂单、条件挂单的相关查询均为签名 `USER_DATA` 读取接口。普通挂单和条件挂单需分别查询。官方支持不授予交易权限的读取模式，但具体账户权限需通过只读连通性验证，不能为解决读取失败而默默增加交易权限。[账户接口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/account)、[持仓及订单接口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)、[Futures 鉴权](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/general-info)
- API 可读取现有持仓的当前强平价，但不是拟开仓的强平价模拟接口。接入 API 后，成交前仍需基于拟成交参数估算；成交后才可使用 Binance 返回的当前实际持仓值核验，且该值可能随后续仓位、保证金和费用变化。[持仓查询](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/trade)
- 开仓成本还涉及 Open Loss 和依订单类型/方向定义的估值价格；只用名义价值除以杠杆会漏掉资金需求。[开仓成本](https://www.binance.com/en/support/faq/detail/87fa7ee33b574f7084d42bd2ce2e463b)、[保证金校验](https://www.binance.com/en/support/faq/detail/4f83b65d83654b5e933f85ef12bf769d)
- Reduce-only 退出存在最小名义价值豁免，其他数量规则仍需按适用场景校验。[USDT 合约规则](https://www.binance.com/en/support/faq/detail/360033161972)、[过滤器定义](https://developers.binance.com/en/docs/products/derivatives-trading-usds-futures/common-definition)
