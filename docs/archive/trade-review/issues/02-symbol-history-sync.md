# 02: 单币种真实历史同步

**What to build:** 使用者选择一个 USDT 永续合约并主动同步最近 3 个月的真实历史，看到读取进度、可确认的完整交易和不完整记录。订单、成交及费用原始证据长期保存，失败或分页未完成时清楚展示缺口，可再次发起补查。

**Blocked by:** 01 — 复盘入口与单笔持久归档。

**Status:** completed

- [x] 提供选择合约、开始同步、查看进度和结果的完整流程；仅使用后端固定白名单 GET，账户设置及交易操作仍由用户在 Binance 执行。
- [x] 同步前验证只读权限和账户身份；同账户换密钥沿用归档，不同账户及真实或模拟模式隔离，身份无法确认时保留旧账本并暂停新增归档。
- [x] 分批读取最近 3 个月的成交、普通订单、条件订单及收入流水，遵守各来源的当前时间窗口和分页规则；达到单页上限不代表全部读取完成。
- [x] 读取和保留可关联的强制订单证据以识别强平或 ADL；普通市价、限价类型不足以确认退出原因，缺失订单元数据显示未知。
- [x] 先让单向单次入场与完整退出的交易可查看，其他暂不支持的复杂成交链保留为不完整记录，待交易周期归并任务扩展。
- [x] 起点以完整成交链和可对账持仓证据确定，不假设同步边界时账户空仓；缺少可靠起点、交易期间证据或退出时点时说明原因。
- [x] 手续费和已实现盈亏按来源关联，资金费计入正负收支；非 USDT 费用保留原资产数额，换算或归属不可靠时净盈亏待确认。
- [x] 原始记录、分页进度、完成区间和失败状态可持久恢复；重复同步幂等，失败或未完成的分页不推进完整性状态。
- [x] 页面显示查询范围、最后成功时间、进度及缺失项；迟到响应、会话失效和失败不把旧结果标成最新或完整，不静默改用模拟数据。
- [x] 从公开入口用替换的 Binance 响应验证多页、时间分片、缺少起点、权限或身份失败、限流、非 USDT 费用和重启补查，并验证浏览器同步状态。

## 实现与验收记录

2026-10-13：用户确认稳定 UID 无法验证时停写；单次入场按单个订单理解，允许多笔成交；当前持仓与完整成交链对账反推起点；重启后由用户主动继续补查，定时与全账户同步留给任务 04。本轮未连接真实账户。

新增 `src/history-sync.ts`，复用固定 GET 签名入口及 BigInt 十进制计算，分批读取成交、普通/条件订单、收入和分别指定 LIQUIDATION/ADL 的强制订单。成交与订单满页继续细分时间，收入按页码读取；同一毫秒达到来源上限或分页未前进时保留未完成与原始证据。90 天订单期限与滚动 3 个月期限之外的区间明确留缺口，不推导完整性。UID 与来源共同隔离 SQLite；原始来源 ID 保留 int64 文本，不使用 API Key 作为账户 ID。

原始证据与分页进度原子提交，冲突或失败不推进该页完成区间；未知成本可补齐，已知事实被改动或抹去则拒绝覆盖。保存归并版本，先支持单个入场订单的单向周期；缺起点、未退出、复杂链、未知或非 USDT 费用均保留不完整记录。账户未能确认、失败或中断时保留旧账本；不同币种的续查优先显示本次活动任务，最近发起时点持久化。

`/review` 提供合约选择、主动同步、进度/缺口、最后成功时间及原始证据分页查看；浏览器隐藏或离开只取消页面请求，已启动同步继续运行，服务停止后保留进度待用户续查。HTTP POST 仅触发本机同步，交易所操作仍全部为固定白名单 GET。

最终 `pnpm check` 通过类型、lint、格式、生产构建、222 项 Node 测试和 98 项 Chromium/WebKit 测试；新增 22 项历史同步 HTTP 测试，复盘浏览器共 14 项，覆盖 320/390/1280px、同步失败补查、会话失效和迟到响应；已检查手机截图。Standards / Spec 双轴审查与复查无剩余问题。审查中的跨币种进度、新增不完整成交漏投影和未知费用无法补齐均以公开 HTTP 红→绿回归修复。

实体手机、真实只读账户 UID/主子账户兼容性及 Binance 实际分页联调尚未验收；模拟响应不能替代真实联调。复杂周期归并、每五分钟持续归档与全账户发现依各自后续任务实施。
