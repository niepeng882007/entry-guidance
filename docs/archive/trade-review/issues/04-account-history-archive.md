# 04: 全账户历史与持续归档

**What to build:** 使用者能同步当前账户全部 USDT 永续历史，查看全账户读取范围、进度和缺口。服务运行期间每 5 分钟持续增量归档，页面关闭仍可同步，服务重启后补查，并提供立即同步操作。

**Blocked by:** 02 — 单币种真实历史同步。

**Status:** completed

- [x] 初次发现并分批读取最近 3 个月的历史交易合约，覆盖未经过本工具的交易及历史已交易合约，不能仅依赖当前可交易币种列表。
- [x] 复用已完成的单币种同步与当前归并能力，列表展示可确认交易及缺口；尚未具备复杂归并能力时相关成交链明确为不完整，不宣称所有周期已确认。
- [x] 服务运行期间每 5 分钟增量同步，提供立即同步；同一账户的重叠请求合并或协调执行，不堆积并发任务或重复记录。
- [x] 浏览器关闭不停止归档；电脑或服务停止期间暂停，重启依据持久进度补查。超过上游可查期限的区间保留缺口，不承诺恢复不可查询历史。
- [x] 分来源、合约和区间记录进度与完整性，失败或未读完分页不推进完成区间；未能发现或读取的合约范围明确披露。
- [x] 权限、身份、限流和网络失败可识别；同账户换密钥延续账本，不同账户及真实或模拟模式隔离，身份无法确认时停止新增归档。
- [x] 页面展示全账户总进度、合约进度、最后成功时间和缺失区间；后台同步不触发 LLM 调用，也不改变原开仓方案或止损核验状态。
- [x] 与现有账户及核验读取协调外部请求，保留访问保护和凭据脱敏；归档只读，不修改交易所状态。
- [x] 用受控时钟和替换响应验证多合约发现、已下架合约、关闭页面后同步、重启补查、并发触发、限流恢复及过期缺口，并验证浏览器进度展示。

## 实现与验收记录

2026-10-14：用户确认联合全账户收入流水、当前 USDT 永续及已归档合约发现历史，持续披露未知范围，不自动使用共享额度的历史下载。正式真实服务配置持久账本后启动即归档，每五分钟触发增量或续查；关闭页面继续，停机暂停，重启补查。运行任务合并重复触发，未完成合约优先，避免限流后被已完成合约的重复读取阻塞。

新增 `src/account-archive.ts`，复用 `HistorySync` 和归并版本 2；SQLite 按来源和稳定 UID 保存全账户发现、合约分页、完成区间及过期缺口。收入按原合约保存，收入来源身份跨发现与单合约查询统一校验，事实冲突原子回滚。成功后只增量读取并保留七天重叠窗口；原有完成区间保留，过期的已有覆盖不误报缺失。收入分页范围因可查边界移动而变化时，清除旧页码与指纹，拆成更小时间片重读，避免重复第一页或跳页；部分过期页直接读取，避免因保存耗时反复裁切。

接入最新 main 的 `coordinateAccountReads`：前台、核验和归档共用外部队列及权重预算；真实归档 GET 间隔至少一秒，最多使用共享预算的 75%，预算不足仅暂停归档，429/418 沿用统一退避。签名在实际发送时更新。身份与权限每轮及发现/合约阶段重新确认，无法确认即停止新增，已有账本保留；手动恢复成功清除此前后台启动问题。

`/review` 展示全账户发现范围、读取总进度、合约进度、最后成功时间及待补查/过期区间，支持立即同步和单合约补查。隐藏或离开只取消页面读取，服务端归档独立于会话。没有新依赖、自动 LLM 调用或交易所写请求。

新增 16 项公开 HTTP、transport 与受控时钟测试，覆盖多合约及已下架合约、满页与移动可查边界、无浏览器触发的五分钟归档、关服/重启、过期缺口、并发合并与账户读取协调、限流恢复、权限/身份/网络失败、跨来源冲突、配额余量及派发时签名。完整 `pnpm check` 通过类型、lint、格式、构建、286 项 Node 测试和 162 项 Chromium/WebKit 测试；复盘页覆盖 320/390/1280px，已目视检查手机截图。已保留最新 main 的账户刷新、笔记、方案对照、首页/侧栏及滚动条布局修复；归档期间打开详情不打断笔记草稿，已知 UID 的未同步空态正常展示。全账户收入查重使用独立查询索引，另通过 56 项账本/归档/历史定向测试。

Standards / Spec 最终复查均无未解决发现；审查发现的跨来源收入冲突、部分过期循环、移动边界满页重置及恢复后旧暂停提示已修复并回归。实体手机、真实只读账户 UID/主子账户与实际分页/限流联调未验收；来源之外无法发现的合约及超过上游可查期限的区间仍明确为缺口，不承诺历史无遗漏。
