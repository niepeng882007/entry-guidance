# 独立账户快照页规格

## 当前页面范围（2026-10-14）

使用者确认账户快照页只展示资产：账户权益、可用余额、未实现盈亏，以及资金占用和查询信息。移除持仓、活跃委托模块及切换和筛选入口，页面不再请求持仓、普通委托、条件委托详情接口，也不单独读取辅助行情。保留现有后端只读入口和开仓、止损核验所需的读取能力。

“资金占用与查询信息”每次进入页面默认展开，仍可手动收起；自动和手动刷新均保留本次页面内的展开状态。资产正常前台仍每轮查询完成后等待 30 秒刷新，工作台摘要保留 3 秒；会话、取消、旧值保留、来源与时间验证、限流及失败冷却继续适用。

异常信息栏只展示简短的失败原因和需要用户执行的操作；已有旧金额时统一标记“数据待更新”。删除页面隐藏、离开、关闭、返回后重新查询、等待首次查询、尚无成功数据、旧值与时间保留、有效状态撤销等机制说明。断网显示“网络已断开”，登录过期保留重新登录入口；限流和冷却只提示稍后自动重试，不展示具体允许读取时间。数据校验失败统一提示“账户数据异常，请重新查询”；后端和浏览器原始错误放入默认收起的“错误详情”，重新查询时清除旧错误。正常成功时不显示信息栏，尚无数据的首次查询由刷新状态和金额占位表达。

## Problem Statement

现有工作台的账户快照能定时显示 USDT 合约账户权益、可用余额、钱包余额、未实现盈亏与查询时间，但缺少面向全账户的持仓和活跃委托详情。使用者需要切换到 Binance 才能掌握各标的当前价格、浮动盈亏、持仓参数及挂单状态，无法在本工具内完整查看查询时点的账户状况。

使用者希望在独立的手机页面中快速掌握账户全貌，并按需查看详细参数。自动刷新应保留浏览位置与展开状态，明确区分成功数据、旧数据和查询失败，避免将旧快照、缺失字段或挂单存在误认为当前有效状态或止损核验通过。

## Solution

新增受登录保护、可直接访问的独立账户快照页，展示当前单个 Binance 普通 USDT 单资产账户的资产、全部 USDT 本位永续持仓及活跃委托。工作台保留原有账户信息和每 3 秒刷新，并提供账户详情页入口。

页面以账户权益、可用余额与未实现盈亏为概览，提供持仓和活跃委托切换、标的筛选及记录详情展开。正常前台每 30 秒更新，返回页面主动刷新并遵守冷却；各分项保留对应查询时间，失败分项明确标记过期，其他成功分项仍可更新。

视觉延续现有黑白简洁风格，以数字对齐、清楚的层级和留白组织信息。颜色仅表达盈亏和异常，使用轻微数值变化与展开动效，并支持减少动态效果。账户读取继续保持只读，交易执行仍由使用者在 Binance 完成。

## User Stories

1. 作为账户使用者，我希望直接打开独立账户页，以便集中查看当前账户详情。
2. 作为工作台使用者，我希望通过明确入口进入账户页，以便在开仓规划与账户观察之间切换。
3. 作为账户使用者，我希望随时返回工作台，以便继续处理原有开仓方案。
4. 作为工作台使用者，我希望原账户摘要和刷新继续可用，以便新增页面后仍能看到原有账户信息。
5. 作为账户使用者，我希望页面和数据均需要登录，以便保护私人账户信息。
6. 作为账户使用者，我希望从账户页退出登录后不能继续读取账户数据，以便结束访问。
7. 作为账户使用者，我希望清楚区分模拟与 Binance 数据，以便不会将演示值当作真实账户事实。
8. 作为账户使用者，我希望突出显示账户权益，以便快速掌握合约资产规模。
9. 作为账户使用者，我希望权益、钱包余额和未实现盈亏分别显示，以便理解权益由钱包余额与未实现盈亏构成。
10. 作为账户使用者，我希望单独看到可用余额，以便区分可用资金与总权益，避免重复扣除占款。
11. 作为账户使用者，我希望展开查看持仓初始保证金、委托初始保证金、维持保证金与可转出额，以便了解资金占用。
12. 作为账户使用者，我希望金额保持准确精度并明确 USDT 单位，以便避免将金额、数量或比例混淆。
13. 作为账户使用者，我希望显示成功查询时间与最近尝试时间，以便判断数据新鲜程度和刷新是否失败。
14. 作为账户使用者，我希望查看全部当前持仓，包括未经本工具生成方案的持仓，以便掌握全账户敞口。
15. 作为账户使用者，我希望全仓与逐仓持仓都能显示，以便不会因开仓工具的限制遗漏已有仓位。
16. 作为双向持仓使用者，我希望同一标的的多头与空头分开显示，以便看清不同方向的敞口。
17. 作为账户使用者，我希望持仓主览显示标的、方向、保证金模式与杠杆，以便快速识别仓位。
18. 作为账户使用者，我希望看到持仓数量和入场均价，以便了解已经形成的持仓参数。
19. 作为账户使用者，我希望标记价作为持仓主价，以便使用与未实现盈亏估值相关的价格口径。
20. 作为账户使用者，我希望最新成交价作为辅助信息并明确命名，以便区分不同价格的含义。
21. 作为账户使用者，我希望每份持仓显示交易所返回的未实现盈亏 USDT 金额，以便掌握查询时点的浮动盈亏。
22. 作为账户使用者，我希望未实现盈亏与扣除手续费、资金费后的净收益区分表达，以便不误读收益。
23. 作为账户使用者，我希望展开查看仓位名义价值、当前强平价、保本价及逐仓资金，以便进一步了解持仓参数。
24. 作为账户使用者，我希望查看可读取到的资金费率与下次结算时间，以便了解相应资金费信息的查询状态。
25. 作为账户使用者，我希望同时查看普通挂单与条件挂单，以便掌握全部活跃委托。
26. 作为账户使用者，我希望委托主览显示标的、买卖方向、持仓方向与订单类型，以便识别委托用途。
27. 作为账户使用者，我希望委托价与触发价按订单类型明确表达，以便不将触发条件当成保证成交价格。
28. 作为账户使用者，我希望普通委托显示原数量、已成交量与剩余量，以便理解部分成交后的状态。
29. 作为账户使用者，我希望整仓退出条件单用整仓语义表达，以便不将未指定固定数量误认为零数量。
30. 作为账户使用者，我希望看到委托状态及可读到的创建、更新时间，以便判断查询时点的订单状况。
31. 作为账户使用者，我希望展开查看委托标识、触发依据、只减仓、整仓退出、价格保护及适用的有效方式，以便自行核对设置。
32. 作为账户使用者，我希望看到止盈止损条件委托而不自动得到“已保护”或“核验通过”状态，以便区分账户事实与方案核验。
33. 作为账户使用者，我希望委托从活跃列表消失时只更新当前列表，以便不会被误告知该委托已成交或已撤销。
34. 作为账户使用者，我希望在持仓与活跃委托之间切换查看，以便手机页面保持简洁。
35. 作为账户使用者，我希望按标的筛选并区分筛选结果数量与全账户数量，以便专注目标合约而不误读总体情况。
36. 作为账户使用者，我希望记录默认按标的与持仓方向保持稳定顺序，以便刷新时不会频繁跳动。
37. 作为账户使用者，我希望刷新保留筛选、仍存在记录的展开状态和键盘焦点，以便持续阅读详情。
38. 作为账户使用者，我希望正常前台每 30 秒更新全部信息并能手动刷新，以便节省额度并按需获取最新可读取状态。
39. 作为账户使用者，我希望已有查询忙时不重复发起同一读取，以便避免刷新堆积。
40. 作为账户使用者，我希望离开或隐藏页面时暂停、返回时立即重新查询，以便节约读取额度并明确离开期间没有监控。
41. 作为账户使用者，我希望断网时保留旧值和原时间、恢复联网后重新查询，以便知道数据已失效且可以恢复。
42. 作为账户使用者，我希望迟到响应不能覆盖更新后的状态，以便不会看到倒退或来源不一致的数据。
43. 作为账户使用者，我希望某一分项读取失败时其他成功分项仍更新，以便尽可能掌握已知事实。
44. 作为账户使用者，我希望失败分项保留旧值并标明过期、没有成功数据的分项显示等待或失败，以便不把未知余额当成零或将查询失败当成空仓。
45. 作为账户使用者，我希望成功确认空仓、无委托与筛选无结果分别显示，以便理解没有记录的真实原因。
46. 作为账户使用者，我希望缺失字段与不适用字段分别表达，以便不把默认值当成交易所返回的事实。
47. 作为账户使用者，我希望多个页面的重复读取被合并，并在限流或持续失败时明确退避，以便刷新保持可用且不将旧值伪装为实时。
48. 作为账户使用者，我希望会话失效时停止查询并显示重新登录入口，以便恢复合法访问。
49. 作为账户使用者，我希望长委托标识与高精度数值在手机上完整可读、键盘焦点可见，以便在窄屏或辅助操作下使用全部功能。
50. 作为账户使用者，我希望轻微动效只帮助识别变化并尊重减少动态效果设置，以便高频刷新不会干扰阅读。
51. 作为开仓工具使用者，我希望账户详情不会改写本单冻结预算、绝对止损或自动恢复核验通过，以便保留原有风险与核验规则。
52. 作为账户使用者，我希望凭据始终留在后端、任何读取错误都不会泄露秘密或扩大权限，以便安全使用只读账户功能。

## Implementation Decisions

- **覆盖范围：** 单人、单 Binance 普通 USDT 单资产账户；展示全部 USDT 本位永续当前持仓和活跃委托，包括全仓、逐仓、单向及双向。双向的多头与空头分别表达。仅扩大账户观察范围，正式开仓与原有止损核验的支持模式继续遵循既有规则。
- **模块职责：** 扩展后端账户读取与 HTTP 服务入口，增加全账户详情汇总、独立账户页面及其刷新状态管理；工作台仅增加详情入口并保留已有摘要行为，样式复用现有主题、组件和变量。
- **读取入口：** 新增受现有登录保护的只读账户详情入口；保持既有账户摘要契约兼容。详情入口不复用要求目标合约空仓的开仓前行情检查，不要求账户当前没有持仓或挂单。
- **响应语义：** 明确数据来源、最近尝试时间，以及资产、持仓、普通委托、条件委托和辅助行情各自的成功查询时间与失败状态。不能用一个新的总时间覆盖旧分项时间，也不能暗示分别读取的值属于同一交易所原子快照。观察页在接收时允许最多 60 秒的查询时间差，覆盖 30 秒缓存与传输时间；超过上限仍判无效，正式开仓和核验的时间要求不变。
- **账户资产：** 主览展示账户权益、可用余额和未实现盈亏；展开显示钱包余额、持仓初始保证金、委托初始保证金、维持保证金、可转出额及查询信息。权益沿用 USDT 钱包余额加未实现盈亏的口径，可用余额采用交易所返回值。
- **当前持仓：** 主览显示标的、多空、保证金模式、杠杆、数量、入场均价、标记价及未实现盈亏 USDT；展开显示最新成交价、仓位名义价值、当前强平价、保本价、逐仓资金、可读取到的资金费率和下次结算时间，以及对应数据时间。
- **活跃委托：** 普通与条件挂单均覆盖；主览显示标的、买卖方向、持仓方向、订单类型、适用的委托价或触发价、数量及剩余量和状态。展开显示标识、创建与更新时间、触发依据、只减仓、整仓退出、价格保护及适用的有效方式。
- **事实与推论：** 标记价、最新成交价及入场均价分别命名；未实现盈亏采用交易所返回值，不作为已扣成本的净收益。整仓退出委托不以零数量展示。止损委托存在不等于止损覆盖已核验，委托消失不推断为成交、撤销或过期。
- **精度与字段验证：** 金额、数量及剩余量继续使用既有 BigInt 十进制定点入口，保持交易步长和精度。验证必要标识、数值、来源与时间；未知字段和不适用字段分别表达，不填入推测值。辅助行情缺失不应将已知持仓误显示为空。
- **页面组织：** 页首提供返回工作台、刷新状态、手动刷新与退出登录；资产概览后是可展开的账户明细，再是持仓与活跃委托切换区。支持标的筛选，默认按标的及持仓方向稳定排序，区分筛选数量与全账户数量。
- **刷新体验：** 独立账户页正常前台每轮读取结束后等待 30 秒再更新全部信息，手动刷新同样重置计时。手动刷新旁只显示随剩余时间缩短的 SVG 圆环，不显示秒数；刷新中显示「刷新中…」，限流、离线、失败、登录失效及模拟数据提示保留，正常查询成功、真实来源说明和只读徽标不占用主览。自动读取在服务端最多复用 30 秒内的成功分项，保留原查询时间。首次进入、手动刷新、返回页面与联网恢复主动触发新查询，仅合并正在进行或 2.9 秒内的邻近成功读取，不能绕过冷却。工作台摘要仍每 3 秒刷新；正式开仓与核验不使用此观察缓存。隐藏、离线或关闭时暂停，离开时取消待完成的页面请求，丢弃迟到响应。
- **失败与恢复：** 分项读取失败时其他成功分项可以更新；失败分项保留旧值与原成功时间并标过期。尚无成功数据时不得使用零余额或空列表替代失败。会话失效停止查询；权限、来源或账户口径无法确认时，不显示当前有效状态。恢复成功不会自动恢复旧方案的核验通过。
- **读取协调：** 合并工作台、独立账户页及多标签页的重复读取，遇到限流或持续失败时退避，显示原因与最近成功时间。前端遵循后端返回的下次允许读取时间：限流时所有分项暂停请求，普通失败仅暂停对应分项，其他分项仍可刷新。合并不改变原开仓和核验完整查询的语义，不允许过期缓存继续提供可执行建议。
- **视觉与状态：** 延续系统字体和黑白风格，以数字对齐、间距和层级组织信息；颜色仅用于盈亏与异常。刷新保持焦点、筛选及仍存在记录的展开状态。数值更新和展开仅用轻微透明度或位移动效，遵循减少动态效果偏好，不每次刷新闪动整页。
- **响应式与可访问性：** 手机优先，同时适配桌面；长标识和高精度金额可完整阅读，没有横向溢出。复用已有原生表单、按钮、展开控件及焦点规则，状态与错误可被辅助技术感知。
- **执行与凭据：** 沿用后端固定白名单 GET、只读权限校验、会话、Host/Origin 校验、静态资源白名单及生产 CSP。凭据不进入页面、浏览器存储、错误输出或文档，不因读取失败授予交易、撤单、提现、划转或账户设置权限。
- **工程范围：** 沿用现有 Vue、TypeScript、Vite、Node 和包管理脚本；不为本页默认增加路由库、组件库、全局状态库或动效依赖，不增加数据库、后台账本或页面关闭后的监控。

## Testing Decisions

测试边界沿用使用者在整体方案确认中接受的模拟响应与浏览器验收方式。主要集成验证从公开 HTTP 入口进入，唯一业务外部替换边界是现有 Binance 传输响应；不为余额、持仓或委托分别创建新的内部 mock 接口。浏览器验证使用生产构建及现有演示服务器，按已有浏览器测试方式控制响应、时间和页面生命周期。

好测试验证使用者可观察的输出、刷新行为、失败状态与访问边界，不断言私有函数调用顺序、组件内部变量或 DOM 实现细节。读取合并测试可以计数上游请求，以证明不会因多个访问者重复消耗额度；这些计数用于验证行为约束，不固定无关的内部实现步骤。

- **账户集成：** 从登录后的摘要与详情读取入口验证 USDT 权益、可用余额、保证金分项、数值精度、字段缺失及明确来源；参考现有账户 HTTP 测试的受控响应、权限校验、超时与脱敏模式。
- **持仓覆盖：** 受控数据包含逐仓、全仓、单向、双向、多标的与未经工具生成方案的持仓；验证同标的多空分开、标记价与最新成交价明确、未实现盈亏原值、未知字段及当前强平价口径。
- **委托覆盖：** 包含普通挂单、部分成交及条件挂单、固定数量只减仓与整仓退出；验证数量、已成交量、剩余量、触发参数、委托标识、状态，以及缺失与不适用的区别。
- **列表变化：** 成功查询返回空仓或无委托时显示相应空状态；记录移除时更新列表，不归因为成交或撤销。筛选无结果与全账户无记录分开验证。
- **定时与并发：** 使用受控时钟验证账户页正常 30 秒刷新、工作台摘要仍为 3 秒、已有查询忙时跳过、手动刷新不堆积，以及多标签页在 30 秒窗口内复用原成功时点、主动读取不受长缓存阻挡。参考现有工作台固定周期与请求取消测试。
- **离开与返回：** 验证隐藏、关闭、离线时暂停或取消，返回和联网恢复立即读取；较旧、已取消或来源不一致的响应不能覆盖当前状态。
- **分项失败：** 单独使资产数值、持仓、普通委托、条件委托或辅助行情不可用；验证允许继续更新的成功分项、失败分项旧值与原时间、没有成功数据的失败状态。权限或账户口径无法确认时验证整体有效状态撤销。
- **限流与恢复：** 受控限流或持续失败导致可观察的退避、原因和时间说明；退避期间多个页面不反复触发上游，恢复后重新查询。人工刷新不能绕过上游退避要求。
- **会话与访问：** 未登录、新增页面入口、数据入口与构建资源的访问规则正确；退出或会话失效后停止读取。非法路径、方法和参数不能成为任意签名代理；生产 CSP 不被放宽，错误不泄露凭据或签名请求。
- **交互与视觉：** 在 320px、390px 与 1280px 验证完整字段、标识和金额没有横向溢出；检查持仓与委托切换、筛选、数量说明、详情展开、稳定顺序、刷新后的焦点与展开保留，并验证减少动态效果偏好。
- **原功能回归：** 原工作台六项账户信息与每 3 秒刷新保留；已有输入、草稿、开仓卡、复制、方案恢复及核验行为保持。资金变化和读取失败继续撤销相关当前状态，不改写冻结预算与绝对止损，不自动恢复通过。
- **完整检查：** 实施完成后运行项目现有完整检查入口 `pnpm check`。本次仅整理规格，不以文档检查替代应用测试，不把官方说明、模拟响应或浏览器视口验收记为实体手机或真实账户验收。

## Out of Scope

- 历史已成交、已撤销或已过期订单列表，完整交易周期归并、复盘账本、净盈亏分析、个人笔记、模型报告及历史同步；这些属于独立交易复盘需求。
- 收益率百分比，包括杠杆收益率、保证金收益率与价格收益率；未实现盈亏先以 USDT 金额表达。
- 图表分析、K 线、历史权益曲线、历史盈亏曲线及基于图形的敞口分析。
- 现货、COIN-M、非 USDT 保证金、多资产、组合保证金、多 Binance 账户或多用户。
- 对全仓或双向持仓生成新的开仓方案或扩大既有止损核验支持模式。
- 自动下单、撤单、止盈止损调整、杠杆或保证金设置、资金划转、提现及任何账户写操作。
- 将账户快照变成自动止损覆盖核验、风险通过判断或未来成交保证。
- 每秒刷新、WebSocket 连续行情推送、页面关闭后的持续监控、后台轮询和通知。
- 手填数据兜底、真实模式失败时回退模拟数据，或以未知和过期数据生成当前有效状态。
- 新增公网部署、域名、数据库、分析追踪、遥测或与账户详情无关的网络集成。
