# 交易复盘规格

状态：设计决策及 12 项任务拆分已确认；2026-10-13 已生成本地任务，任务 01–03 已实现演示归档、复盘入口、单币种真实历史同步与复杂周期归并，任务 05 已实现个人笔记与风格标签；06 已实现原方案与查询时点证据留存、严格关联和执行对照；09 已实现单笔双来源历史行情及事件图；04、07、08、10–12 待实现；真实账户联调未验收。

## 已确认范围

| 决策 | 确认结果 |
| --- | --- |
| 主记录 | 以从空仓到再次空仓的一笔完整交易为单位；详情展开订单和逐笔成交。 |
| 账户覆盖 | 当前 Binance 账户全部 USDT 本位永续交易，包括未经本工具生成方案的交易。 |
| 分析重点 | 表现规律与执行问题为核心；单笔复盘与个人笔记提供具体交易的背景。 |
| 加减仓与反手 | 未归零前的加减仓归为同一周期；反手拆为旧周期结束和新周期开始，保留原成交关联。见 [ADR 0004](adr/0004-trade-cycle-grouping.md)。 |
| 历史持仓模式 | 全仓、逐仓、单向、双向都覆盖；双向的多头与空头分别归并。无法确认的历史杠杆、保证金模式等显示未知。 |
| 记录状态 | 保留持仓中、已结束及数据不完整记录；净盈亏归属未确认时展示待确认及已知分项。 |
| 统计样本 | 胜率、平均净盈亏等默认仅使用已结束且对应数据完整的交易；展示有效样本数和排除数量。 |
| 赢亏判定 | 以复盘净盈亏判断，详情分别展示已实现盈亏、手续费与资金费净收支；关键数据不完整时不判定净赢亏。 |
| 首版历史 | 首次同步最近 3 个月并持续归档；更早历史后续补录。 |

领域定义见 [词汇表](../CONTEXT.md)。本功能扩展现有规格对完整交易历史的排除；开仓与止损功能的风险及执行边界继续以 [产品决策](product-spec.md) 和 [ADR 0003](adr/0003-readonly-account-verification.md) 为准。

## 已确认数据留存与同步

- 服务端本地账本长期保存，手机与电脑访问同一份；保存原始成交、订单、费用、方案关联、笔记与报告。退出登录、清除本单和重启服务保留历史。持久化取舍见 [ADR 0005](adr/0005-server-trade-ledger.md)。
- 首次分批同步最近 3 个月；服务运行期间每 5 分钟增量同步，并提供立即同步。页面关闭仍可同步，电脑或服务停止时暂停，重启后补查。
- 展示同步进度、最后成功时间和缺失区间。失败与未读完分页的区间保持未完成；补查不保证恢复已经超过上游可查期限的数据。
- 首版提供交易 CSV 导出、完整备份与恢复，由用户手动下载备份；更早历史补录属于后续工作，恢复备份用于恢复本工具已归档的数据。
- 恢复前校验账户、真实或模拟模式、格式与版本，并预览新增、重复、冲突和拒绝记录。默认补入缺失记录、重复去重；笔记与标签冲突时保留当前版本，将备份版本保留为可查看的旧版本。跨账户备份拒绝混入，已有记录的覆盖由用户明确选择。
- 备份包含原始证据、方案关联、笔记、报告、归并版本与同步状态；恢复在校验通过后原子完成，失败保留当前账本，导入数据不能凭空证明缺失区间已完整读取。

## 已确认记录与笔记

- 筛选：日期、币种、多空、净赢亏、记录状态、入场类型、是否关联方案、风格标签。日期默认按开仓时间，可切换平仓时间；最近开仓排在前面。
- 主列表优先显示币种、方向、状态、净盈亏、开平仓时间及持仓时长。包含不同入场订单类型时显示混合；元数据缺失显示未知。
- 用户填写风格标签和笔记；模型提出的分类单独展示，由用户确认。笔记支持入场理由、退出理由、执行问题、改进事项与自由记录。
- 关联方案的交易对照原预算和止损；没有原计划的历史交易仅依据已有证据分析，不直接判定违反计划。

## 已确认 LLM 分析路径

- 首版内置分析，由用户手动发起单笔或当前筛选范围的分析，后端调用选定模型服务。
- 不设置每日或其他调用次数限制。每次主动发起分析可产生完成全范围所需的分段请求和综合请求；不因页面访问、归档同步或新成交自动调用模型。
- 完备上下文包含所选交易的全部相关成交、订单、费用、原方案、已保存的核验记录、风格标签、用户允许发送的笔记，以及注明周期、来源和时间范围的行情；提供全范围统计与缺失项清单。凭据留在后端，不属于分析输入或备份内容。
- 发起时冻结本次分析范围与证据，记录数据时点和模型配置；后续新增成交或修改笔记不改变运行中的分析依据。同样的数据与笔记可复用已有报告，重新生成由用户主动触发。
- 超出模型容量时全量分段分析后综合，记录每段的交易、时间与证据覆盖范围；不静默截断、抽样或遗漏。综合阶段明确引用分段结果，不能把摘要称为原始证据；任一段未完成，整体报告标为未完成。
- 使用后台长任务，用户可离开页面、查看进度或取消；取消此前提出的固定 16k 输出和 3 分钟等待限制，输出遵循模型可用容量。保留网络异常处理；取消、服务中断、上游失败或输出截断不视为成功，继续或重试由用户明确选择。
- 失败保留已完成的分段结果及已有报告，展示返回的用量和未知用量状态。取消或失败可能仍产生上游费用，不能将未收到使用量解释为免费；不自动重复收费请求。
- 报告按观察、证据、改进建议和下次检查项组织，保存分析范围与数据时间。
- 批量分析使用筛选范围内全部有效交易的统计摘要与逐笔关键事实，首版每次最多 100 笔；超过时要求缩小范围，不静默抽样。此为每次分析范围上限，不是调用次数限制。
- 单笔可分析持仓中或不完整记录，并明确缺项；批量表现结论沿用已结束且对应数据完整的交易口径。
- 当前本地配置指向 DeepSeek、`deepseek-v4-pro`、`high`；存在 `LLM_PROVIDER`、`LLM_MODEL`、`LLM_API_KEY`、`LLM_EFFORT`，现有程序尚未使用这些配置。未调用模型或验证凭据有效性。
- 2026-10-12 查阅[官方 Responses 接口](https://api-docs.deepseek.com/api/create-response/)：该模型可通过 `/responses` 使用 `high` 推理与 JSON Schema 输出，`max_output_tokens` 同时约束可见输出和推理 token。接入细节仍须通过模拟响应测试及授权后的最小实连检查。

## 已确认走势、统计与证据

- 单笔 K 线叠加开仓、加仓、减仓、平仓事件和有关联方案的止损线；默认覆盖持仓期间及少量前后行情，支持切换周期。原计划线与有证据的实际止损设置分别表达。
- 模型接收数值行情与交易事件；评价当时决策只依据当时可见的信息，出场后走势单列为事后观察。
- 首版指标：有效交易数、胜率、净盈亏、平均盈利与平均亏损、盈亏因子、持仓时长；展示累计净盈亏曲线，以及按币种、方向、入场类型、风格标签的分组比较。各组显示样本数，累计净盈亏与账户权益分别表达。
- 赢、亏、持平分别计数；胜率为净盈利笔数除以全部可判定净盈亏的已结束交易数。盈亏因子为正净盈亏总额除以负净盈亏总额的绝对值，没有亏损样本时明确标注不适用。累计净盈亏按平仓时间排列，仅表示筛选范围内的已确认交易结果。
- 有证据的预算偏离、入场偏差和已记录的止损设置偏离可以明确标记；缺少历史证据时显示无法判断。追涨、情绪化、报复交易等依据用户笔记或作为待确认推测。
- 每条分析结论附对应交易、统计分组或笔记依据。结果超出预算与用户违反计划分别表达，不能仅凭亏损推断操作动机或违规。

## 数据正确性约束

以下是已确认归并、净盈亏与长期留存原则的实现约束：

- 反手成交的平仓数量归旧交易，超过原仓位的数量归新交易；成交已实现盈亏归旧交易，手续费按拆分数量比例分配并保留原费用关联，分配尾差归新交易以保持总额不变。计算和显示沿用现有 BigInt 十进制规则。
- 起点须由可对账成交链与持仓证据证明；仅缺少开仓记录或无法证明历史区间完整时保留片段，不假设同步边界当时空仓。
- 非 USDT 费用保留原资产及数额；缺少可靠换算依据或双向资金费无法唯一归属时，相关净盈亏待确认，从相应净盈亏指标中排除。已知分项和账户资金费流水仍可查看。
- 同步先确认服务端读取的账户身份，真实与模拟数据分开；同一账户换密钥沿用归档，不同账户隔离。无法确认身份时暂停新增归档并保留已有数据，不使用密钥作为稳定账户 ID。
- 原计划、查询时点核验与交易所事实分别保存和表达；历史未记录的止损变化、杠杆及人工意图保持未知。
- 同步覆盖历史已交易合约，不能仅使用当前可交易币种列表；未能发现、读取或对账的区间与币种明确列为缺口，不宣称所有历史完整。
- 行情注明合约价格或标记价来源；实际成交标记使用成交价格，止损触发条件按其触发依据解释。K 线无法提供精确的逐笔价格路径时保持相应精度边界。

## 当前实现事实

- 当前方案核验保留原读取契约；任务 01–03 提供独立演示账本、单笔复盘入口、主动单币种历史分片/分页同步和复杂周期归并，尚无全账户历史发现或每五分钟持续归档。
- 浏览器保留当前一笔方案与原 recovery.v1 恢复契约；新生成方案按稳定 UID 连同查询时点核验、成交与止损设置长期保存在 SQLite。核验直接证据唯一匹配时关联交易；歧义或无证据时保持无法关联，缺少历史 UID 的旧凭证不补认领。身份或落盘失败时本次生成/核验明确失败，已有本单和归档保留。开仓仍使用最新行情快照；单笔复盘已通过任务 09 按需读取和归档合约价与标记价历史 K 线，按来源展示范围、时点、完整性与缺口，抽稀图表与原始数据分别表达。行情与事件冻结快照可供后续分析，当前尚未接入模型。
- 历史账户数据不能自动补出当时的亏损预算、计划止损、交易理由或历史核验结果。
- 正式启动的复盘数据目录默认 `.local/review`，可通过 `REVIEW_DATA_DIR` 指定；真实和演示分别使用 `real.sqlite` 与 `demo.sqlite`，真实账户按服务端读取的 UID 隔离。单币种同步保留原始证据、完整区间、缺口及分页进度；失败和服务中断后由用户再次主动同步续查。浏览器隐藏或关闭停止页面轮询，已启动同步继续至完成或失败。备份导出、LLM 集成和定时全账户同步尚未实现。

这些事实用于界定新增工作，不代表复盘已实现或真实账户联调已通过。现有实现与验收状态见 [README](../README.md)。

## 外部数据约束

核验日期：2026-10-12；只查官方说明，未连接真实账户。

- 标准[成交历史接口](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Account-Trade-List)按币种查询，仅可查过去 3 个月，单次时间跨度最多 7 天，最多 1000 条。当前核验读取没有复盘所需的分页同步。
- [普通订单](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/All-Orders)和[条件单](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Query-All-Algo-Orders)创建超过 90 天不可查；未成交取消或过期订单在创建超过 3 天后也不可查。订单元数据缺失不能被解释为未下单。
- [收入流水](https://developers.binance.com/docs/derivatives/usds-margined-futures/account/rest-api/Get-Income-History)仅保留最近 3 个月，资金费流水没有保证提供持仓方向。推论：双向仓位的资金费无法总是精确归属各笔交易，需要明确归属或缺失规则。
- 官方另提供成交、订单和收入的[历史下载入口](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/account)，单次窗口最多 1 年，每类文档列出每月 5 次请求且与网页导出共享额度。窗口长度不等于承诺的历史保留期限；较早历史的获取方式仍待选择与验证。
- 任务 02 使用官方[现货账户查询](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/account)返回的 `uid` 作为稳定账户身份，身份或只读权限无法确认时停写保留旧账本；子账户兼容性及真实账户联调仍待实连，API Key 不作为稳定账户身份。2026-10-13 再次核对 UID、各历史接口窗口/上限、收入页码以及强制订单类型；成交 `fromId` 不与时间范围混用。
- 官方[强制订单查询](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Users-Force-Orders)区分强平与 ADL，可按币种和订单关联；缺少证据时，普通市价或限价类型不能确定退出原因。
- 成交费用包含实际资产，可能不是 USDT；[官方成交接口](https://developers.binance.com/docs/derivatives/usds-margined-futures/trade/rest-api/Account-Trade-List)未提供历史 USDT 换算价格。使用历史行情折算只能表达为估算。
- DeepSeek [模型元数据](https://api-docs.deepseek.com/api/list-models/)描述当前模型上下文与输出容量；[Responses 兼容性说明](https://api-docs.deepseek.com/guides/responses_api/)明确超出上下文窗口会报错，不支持自动截断参数。后续调用不会自动保留之前的原始证据；分段覆盖与最终综合报告必须分别说明依据。
