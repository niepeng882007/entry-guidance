# 扩展为多用户产品，按现有功能等价迁移

2026-10-16 确认：项目扩展为具有公开官网、允许其他人注册并绑定各自 Binance 账户的产品。目标选型为 Next.js、Vercel 与 Neon，允许按现有业务需要保留常驻后端或任务执行服务；统一代码库不要求所有工作都由普通请求函数完成。

相比仅将个人工具搬到云端，此选择新增产品用户与交易所账户的归属、凭据管理及跨用户隔离责任。现有功能、历史数据、未完成本单恢复、手机交互与北京时间口径按等价迁移验收，继续遵守只读 Binance 接入、用户手动交易、固定预算与绝对止损，以及共享 BigInt 计算边界。

此决定取代个人使用、不做多用户注册及部署平台未定的目标限制；[ADR 0005](0005-server-trade-ledger.md) 的服务端长期留存原则继续适用，SQLite 为当前实现，Neon 为迁移目标。现有实现与验收没有因目标确认而改变，仍见[项目现状](../status.md)。

第二轮确认公开邮箱密码注册并验证邮箱；用户与 Binance 账户一对一且 UID 独占，Binance 凭据由平台加密托管，详见 [ADR 0007](0007-account-binding-and-credentials.md)。AI 使用用户自备模型 Key，保留不限调用次数并通过排队控制并发，首版不做平台计费；试运行规模先从小，地区与预算暂缓确定。

第三轮已确认解绑保留原用户只读历史与 UID 占位，注销在线清理完成后释放；AI Key 长期加密托管，平台灾备可包含密文但主密钥独立，灾备最长 30 天到期。采用 [ADR 0008](0008-persistent-business-service.md) 的常驻业务服务与受保护数据直连，旧库短暂停写迁移；首版仅用最小日志，不接 Sentry。

产品分支已收敛，最终[实施计划](../refactor-implementation-plan.md)待用户确认。地区、预算及具体资源保留为上线条件，不把目标确认当作已实施或已验收。
