# 网页与常驻业务服务分工，分离大数据传输

2026-10-16 第三轮确认：Next.js 在 Vercel 提供官网、用户页面与认证，一个常驻 Node 业务服务承接 Binance 读取、开仓核验、账本、归档、AI 排队和数据传输，Neon 保存状态；首版不新增独立队列产品或对象存储。

相比将全部业务放进普通 Serverless 请求，此选择复用现有长任务和读取协调边界，并提供 64 MiB 恢复及较大 AI/统计证据的受保护直连通道。代价是维护两个运行入口、服务间身份校验和共同发布/恢复契约；用户 Key 解密能力仅授予业务服务，Better Auth 仍是唯一登录源。

旧数据先隔离演练和对账，再短暂停写切换，不长期双写。新系统开始写入后，旧 SQLite 只用于只读对账，不恢复可写；恢复必须依据恢复点之外的删除/撤销记录，防止旧快照复活已注销用户或凭据。具体主机、地区和预算在上线前确定，实施及验收见[重构计划](../refactor-implementation-plan.md)。
